# 专项设计：道具系统

> 状态：V0.1 架构草案
>
> 当前范围：PVE 对局携带、主动道具手动使用、被动道具开局全局生效、统一效果与回放。

## 一、核心规则

1. 道具分为主动道具和被动道具，两类使用完全不同的触发方式。
2. 主动道具由玩家在局内手动使用。
3. 被动道具在进入对局后自动全局生效，不需要玩家操作。
4. 道具携带方案在进入对局前确定；对局开始后不能新增、移除或更换已携带道具。
5. 神将自身主动技能仍由系统自动释放，不属于主动道具。
6. 所有道具能力由服务端执行：战斗数值与状态通过统一效果系统表达；改字、刷新托盘等结构变化通过统一规则动作表达。
7. 新版没有扩地操作，任何道具都不能解锁、增加或改变部署地块。
8. 当前只定义 PVE 道具作用域；PVP 是否禁用、标准化或重新平衡，留到 PVP 专项。

## 二、局外配置与开局快照

```ts
interface PlayerItemLoadout {
  playerId: string
  activeItemIds: string[]
  passiveItemIds: string[]
  version: number
}
```

主动与被动道具的携带槽数量由后续整体构筑平衡确定，首版架构使用配置项：

```ts
interface ItemLoadoutRules {
  activeSlotLimit: number
  passiveSlotLimit: number
  allowDuplicateItems: boolean
}
```

创建对局时，服务端复制局外配置形成不可变 `matchItemLoadoutSnapshot`。局外随后发生的配置变化不影响已经开始的对局。

## 三、主动道具

### 1. 触发流程

```text
玩家点击主动道具
→ 若需要目标则进入目标选择
→ 客户端发送 USE_ACTIVE_ITEM
→ 服务端校验携带、次数、CD、资源、目标和对局状态
→ 服务端执行结构化效果
→ 扣除次数/开始 CD
→ 广播结果、表现事件和拒绝原因
```

主动道具不能仅由客户端播放效果或直接修改棋盘状态。

### 2. 主动道具运行时状态

```ts
interface ActiveItemRuntimeState {
  itemId: string
  chargesRemaining: number | null
  cooldownRemainingMs: number
  usesThisMatch: number
  enabled: boolean
}
```

每件主动道具必须明确：

- 使用目标：无目标、棋盘格、托盘格、单个小兵、单个汉字、激活神将、敌人或区域；
- 使用消耗：次数、局内资源、CD，或其组合；
- 失败是否消耗次数和进入 CD；默认校验失败不消耗；
- 效果是否可以命中固定神将中的单个汉字；
- 对大本营、弃置区、召唤托盘和棋盘的合法操作边界。

### 3. 首批主动道具能力类别

| 类别 | 示例方向 | 所需效果/动作 |
| --- | --- | --- |
| 改字 | 将一个汉字变为合法候选字符 | `replace_character_token` 规则动作 |
| 升级 | 为目标神将增加经验或直接升一级 | `grant_general_experience` 规则动作 |
| 召唤干预 | 重新生成部分或全部召唤托盘 | `refresh_summon_tray` 规则动作 |
| 战斗爆发 | 临时提高输出、范围或攻速 | 限时 `stat_modifier` |
| 战场控制 | 对敌人施加减速、眩晕或路径位移 | 统一控制效果 |

具体道具逐个专项设计，不能只根据名称硬编码。

## 四、被动道具

### 1. 生效时机

进入对局并完成玩家状态初始化后，服务端按固定顺序挂载全部被动道具效果：

```text
玩家基础规则
→ 关卡规则
→ 被动道具
→ 后续神将/武器/羁绊运行时效果
```

被动道具从对局开始持续到对局结束，不需要手动触发。若被动包含周期产出或事件监听，其监听器也在开局注册、结算后注销。

### 2. “全局”作用域

默认的全局指 `owner_global`：只影响携带者自己的斋饭、召唤托盘、棋盘单位和神将，不自动影响多人 PVE 队友。确需团队生效的道具必须显式声明 `team_global`，并单独处理同名叠加。

### 3. 首批被动道具能力类别

| 类别 | 示例方向 | 关键边界 |
| --- | --- | --- |
| 经济 | 初始斋饭、周期产出、征兵折扣 | 产出频率与最低召唤成本 |
| 卡池 | 提高字符出现概率、品质倾向 | 不能生成已耗尽的 Token |
| 人口 | 增加基础人口上限 | 与场地空间和召唤物上限分开 |
| 成长 | 提高参与经验、开放突破等级 | 经验总量与上限 |
| 战斗 | 全局攻击、攻速、法强、控制强化 | 统一属性上限 |
| 掉落 | 提高武器碎片掉率或结算数量 | 服务端奖励预算与防重复结算 |

## 五、道具配置结构

### 1. 主动道具示例

```json
{
  "schemaVersion": 1,
  "itemId": "change_character_brush",
  "name": "改字符",
  "itemKind": "active",
  "targeting": {
    "scope": "single_character_tile",
    "allowedZones": ["summon_tray", "board"]
  },
  "runtime": {
    "maxCharges": 2,
    "cooldownMs": 10000
  },
  "actions": [
    {
      "type": "replace_character_token",
      "candidateSource": "remaining_or_recoverable_general_characters",
      "preservePosition": true
    }
  ]
}
```

### 2. 被动道具示例

```json
{
  "schemaVersion": 1,
  "itemId": "field_kitchen",
  "name": "行军灶",
  "itemKind": "passive",
  "activation": "match_start",
  "target": {
    "scope": "owner_global"
  },
  "effects": [
    {
      "type": "resource_modify",
      "resource": "startingRice",
      "operation": "add_flat",
      "value": 10
    }
  ]
}
```

自然语言描述只用于 UI；逻辑使用结构化效果或已注册的规则动作。`effects` 与 `actions` 可以同时存在，但必须分别校验并按配置顺序执行。

## 六、与征兵和棋盘系统的交互

1. 改字道具命中固定神将中的字符前，必须要求玩家先解除固定；避免一次操作暗中破坏整组神将。
2. 改字后立即重新扫描受影响行的神将组合与人口。
3. 托盘刷新道具与普通召唤必须使用同一原子刷新逻辑，但可以声明是否扣斋饭、是否弃置旧内容以及是否消耗大本营有限字符。
4. 人口被动在开局确定基础上限；如果未来允许临时人口效果，效果结束时不能直接删除超额单位，而应禁止继续部署直到人口回到上限内。
5. 被动字符概率加成只影响“是否抽到字符”，实际字符仍从剩余有限 Token 中抽取。

## 七、与神将、武器和羁绊的交互

- 主动道具给神将升级时，目标是 `generalProgressById`，不是某个汉字 Token；
- 神将拆开后，针对该神将的临时道具效果按效果配置继续计时或移除，不能通过重新组合重复获得；
- 被动道具、武器和羁绊修改相同属性时，全部进入统一效果系统既定层级和上限；
- 道具不能在局内更换武器，也不能绕过武器适配与双槽限制；
- 增加武器碎片掉率的被动只修改服务端掉落表，不直接写入永久库存。

## 八、多人 PVE 规则

- 每位玩家使用自己的主动道具次数、CD和局外携带配置；
- `owner_global` 被动只影响自己；
- `team_global` 被动必须声明是否允许同名叠加，默认同名取最高值；
- 主动道具作用于队友单位时必须由道具配置明确允许；
- 所有玩家操作进入同一服务端动作队列，使用权威 Tick 结算。

## 九、首版暂不处理

- PVP 道具禁用表与公平化配置；
- 道具品质、升级、碎片与永久养成；
- 每日清空、赛季轮换等运营规则；
- 主动/被动携带槽的最终数量；
- 道具交易、分解和合成；
- 未注册的脚本型自定义道具。

## 十、首版验收用例

1. 未携带、无次数、CD 中、目标非法的主动道具被服务端拒绝且不消耗。
2. 合法主动道具只执行一次，重复请求保持幂等。
3. 被动道具在开局自动挂载，玩家无需操作，结算后完整移除。
4. `owner_global` 不影响队友，`team_global` 按配置影响全队。
5. 改字、托盘刷新和人口修改均维持棋盘状态一致性。
6. 配置或客户端请求出现扩地动作时被服务端拒绝。
7. 神将拆合不能重置主动道具效果、重复触发被动或重复升级。
8. 局外修改携带方案不影响已经开始的对局。
9. 回放能复现主动使用时机、目标、随机结果和被动效果。
