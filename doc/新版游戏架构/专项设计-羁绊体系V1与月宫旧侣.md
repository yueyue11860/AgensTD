# 专项设计：羁绊体系 V1 与月宫旧侣

> 状态：V1 可执行原型，待嫦娥专项接入后进入数值测试
>
> 首个落点：后羿
>
> 首条羁绊：月宫旧侣（后羿＋嫦娥）

## 1. 为什么首条选月宫旧侣

现有概念表中，后羿同时可向“穿云双将（杨戬＋后羿）”和“月宫旧侣（后羿＋嫦娥）”发展。首条选月宫旧侣，原因是：

- 后羿与嫦娥的神话关系无需额外解释，玩家容易记住。
- 二人都是两字紫将，首轮成型成本可控，便于高频测试组合与拆解。
- 后羿是物理远程，嫦娥可作为召唤远程，第二个神将就能验证跨职业羁绊和召唤物继承边界。
- 首版仅修改已有属性，不新增主动技能，不要求首切片同时完成减速参数补丁。

原《专项设计-羁绊结算.md》中“雷部双神首个原型候选”是旧开发顺序建议。按当前“先后羿、再沿羁绊出将”的要求，首个实际原型以本文为准。

## 2. 按羁绊出将的首批顺序

| 顺序 | 神将 | 当次目标 | 羁绊进度 |
| --- | --- | --- | --- |
| 1 | 后羿 | 跑通两字神将、远程物理普攻、自动技能和成长模板 | 月宫旧侣 1/2，穿云双将 1/2 |
| 2 | 嫦娥 | 验证召唤流与召唤物属性继承 | 正式闭合月宫旧侣 |
| 3 | 杨戬 | 验证破甲和第二条双人羁绊 | 闭合穿云双将 |
| 4 | 哪吒 | 引入范围物理与路径位移，为两条羁绊铺路 | 莲花父子 1/2，天庭先锋 2/3 |
| 5 | 李靖 | 验证一名神将同时使两条羁绊成型 | 闭合莲花父子和天庭先锋 |

这个顺序的原则是每增加 1～2 名神将就有一条可玩羁绊闭合，而不是先做一批互不相关的单将。第 3 名之后的羁绊效果仍须逐条专项定稿，上表只确定开发顺序。

## 3. 分类数据不再混用单一标签

神将的羁绊索引必须拆为四个正交维度：

```ts
interface GeneralSynergyProfile {
  generalId: string
  glyphs: readonly string[]
  factions: readonly string[]       // 阵营，例如 heavenly_court
  profession: 'physical' | 'magic' | 'summon' | 'control'
  playstyles: readonly string[]     // 流派/战斗特征，例如 ranged、critical
  namedCollections: readonly string[] // 有名集合，例如 moon_palace_legend
}
```

语义必须固定：

- `factions` 回答“他属于哪个势力”，不表示职业。
- `profession` 回答“他的核心战斗路线”，同一时间只有一个主职业。
- `playstyles` 回答“他怎么打”，可同时拥有远程、单体、暴击等多个特征。
- `namedCollections` 是策划明确命名的人物集合，不从姓名字符串临时推断。
- “特定组合”不是神将标签，而是羁绊定义中的 `all_generals` 激活条件。

羁绊配置的激活条件使用可辨别联合：

```ts
type SynergyRequirement =
  | { kind: 'all_generals'; generalIds: readonly string[] }
  | {
      kind: 'facet_count'
      dimension: 'faction' | 'profession' | 'playstyle' | 'named_collection'
      facetId: string
      minimum: number
    }
```

一条羁绊可以有多个激活层级，每层使用独立 `requirements + effects`。同时满足多层时只启用最高层，层级变化先移除旧来源，再挂载新来源。当前概念表仍是固定成员羁绊；`facet_count` 是为未来阵营、职业和命名集合扩展预留的明确结构，不代表首版已改为“任意 N 人”。

## 4. 棋盘和组合边界

首版普通羁绊的统计口径固定为：同一玩家、棋盘上、已按正确顺序连续组成的逻辑神将。

| 状态 | 是否计入 | 理由 |
| --- | --- | --- |
| 棋盘上已组成神将 | 是 | 已形成可战斗的逻辑神将 |
| 棋盘上但字序被破坏 | 否 | 神将立即失活 |
| 召唤托盘 | 否 | 字符和单位都是待部署状态 |
| 备战席 | 否 | 不参与普通羁绊和人口 |
| 弃置/流放区 | 否 | 已不在玩家可用阵容中 |
| 其他玩家的同名神将 | 否 | 普通羁绊按玩家独立结算 |

多字神将不按汉字数量计数。“后＋羿”形成一个 `generalId=houyi`，在任何羁绊中只计 1 名后羿。羁绊检测使用 `Set<generalId>`，即使错误状态中短暂出现两个同名投影，也不能冒充两名成员。神将唯一性仍应由上游组合器拒绝异常状态。

`fixed` 只是交互属性：

- “固定↔解除固定”不触发羁绊改变。
- 固定神将整体迁移且字序不变，不触发羁绊改变。
- 解除后移走任一汉字破坏组合，当个服务端动作结算中使神将和相关羁绊失活。
- 再次组成时恢复同一 `ownerPlayerId + generalId` 成长身份；羁绊不创建新经验、等级或 CD 记录。

## 5. 检测时机与增量结算

不在每个战斗 Tick 全量扫描羁绊。仅在下列权威状态事件后评估受影响玩家：

1. 新神将首次形成。
2. 某个字被移走、交换、流放或改字，导致神将失活。
3. 托盘/备战席/棋盘的原子交换完成后，如果造成神将激活集合变化。
4. 断线重连、存档恢复或回放加载时全量重建一次，并与快照羁绊集合校验。
5. 未来如有会修改神将分类快照的局内规则，只能在服务端确认快照版本变更后重算。

固定状态改变、不破坏组合的整体迁移、神将经验升级都不改变“哪些羁绊激活”。经验升级只需触发有效属性重算。

结算流程：

```text
组合器产生 GeneralFormationProjection[]
→ 按 ownerPlayerId 筛选 board + isFormed
→ 去重得到 Set<generalId>
→ 选出每条羁绊的最高满足层级
→ 与上一版 ActiveSynergyState 比较
→ 产生 apply_effects / remove_source 命令
→ modifierVersion + 1
→ 重算受影响神将及白名单继承的存活召唤物
```

## 6. 月宫旧侣 V1 效果

### 6.1 激活和对象

- `synergyId`：`moon_palace_companions`。
- 成员：`houyi` 和 `chang_e`。
- 激活：同一玩家的两名神将都在棋盘上且已组成。
- 对象：仅两名羁绊成员的神将本体。
- 层级：首版只有 1 层。

### 6.2 结构化效果

```json
{
  "synergyId": "moon_palace_companions",
  "displayName": "月宫旧侣",
  "category": "specific_combination",
  "activationScope": "owner_board_formed_generals",
  "levels": [
    {
      "level": 1,
      "requirements": [
        { "kind": "all_generals", "generalIds": ["houyi", "chang_e"] }
      ],
      "effects": [
        {
          "effectId": "moon_palace_companions_range",
          "type": "stat_modifier",
          "target": { "scope": "synergy_members" },
          "stat": "attackRange",
          "operation": "add_flat",
          "value": 500,
          "stackGroup": "synergy_attack_range"
        },
        {
          "effectId": "moon_palace_companions_attack_speed",
          "type": "stat_modifier",
          "target": { "scope": "synergy_members" },
          "stat": "attackSpeed",
          "operation": "add_ratio",
          "value": 1000,
          "stackGroup": "synergy_attack_speed"
        }
      ]
    }
  ]
}
```

数值单位与后羿 `hero-v1` 保持一致：

- `attackRange +500` 表示半径增加 0.5 格，后羿从 3000 提升为 3500 milli-cells。
- `attackSpeed add_ratio +1000` 表示攻速提高 10%，比例统一使用基点，`10000 = 100%`。
- 不新增技能，不修改后羿穿云逐日箭的伤害系数。
- 不在 V1 实现原概念中“减速幅度提升 20%”；该效果必须等嫦娥和减速参数补丁完成后单独平衡。

### 6.3 首轮数值预期

对 1 级后羿：

- 无羁绊：射程半径 3.0 格，攻击间隔 1350ms。
- 月宫旧侣：射程半径 3.5 格，攻击间隔约 1228ms。
- 在目标持续停留于射程内的理想条件下，普攻 DPS 理论提升约 10%；射程收益体现为更早开火与更长输出窗口，不应再按 0.5 格折算一次直接伤害。

## 7. 属性叠加、冷却与召唤物接口

### 7.1 属性叠加

每个修改器必须带：

```text
source.kind = synergy
source.sourceId = synergyId
target + stat + operation + value + stackGroup
```

同层 `add_flat` 求和，`add_ratio` 以基点求和，再进入统一属性流水线。羁绊失效时执行 `remove_source(synergyId)`，不从当前最终属性上手工减回数值。手工减回会在多羁绊、武器和道具叠加时产生漂移。

### 7.2 冷却上限

月宫旧侣 V1 不修改 CD，但羁绊执行器预先固定全局边界：

- 常驻冷却缩减上限 40%，即 4000 基点。
- 最终技能 CD 不得低于 1000ms。
- 羁绊、武器、被动道具的常驻减 CD 先求和再截断，不分别截断后相乘。
- 击杀减 CD 是事件效果，必须另有单次值和每次释放周期的触发上限。

### 7.3 召唤物继承

羁绊效果是否作用于召唤物，不能由“全属性”、“友军”或职业名自动推断：

- `target.scope=synergy_members` 只挂给神将本体。
- `target.scope=owned_summons_of_synergy_members` 才直接修改召唤物。
- 如果召唤物模板的继承白名单包含“主人最终攻速”，成员本体的攻速变化可通过该白名单间接更新；如未包含则不继承。
- 主人升级、羁绊启停或武器来源变化后，`modifierVersion + 1`，只重算该主人已存活的召唤物，不每 Tick 重算。
- 拆解神将后召唤物是立即退场还是自然结束，由召唤效果的 `sourceInactivePolicy` 决定；羁绊系统不覆盖它。

## 8. 主链接入状态

羁绊内核仍保持纯函数；主 PVE 已完成首个后羿切片需要的边界：

1. **神将组合器→羁绊：已接入**
   - 输出 `GeneralFormationProjection[]`，包含 `ownerPlayerId/generalId/zone/isFormed/isFixed/constituentTokenIds`。
   - 组合器是汉字连续与字序的唯一权威来源。

2. **权威动作完成→评估：已接入**
   - 在每个会改变神将激活集合的原子动作成功后，调用 `evaluatePlayerSynergies(...)`。
   - 调用 `reconcilePlayerSynergies(previous, next, definitions)` 生成增量命令。

3. **羁绊→统一效果系统：首切片已接入，通用执行器待专项扩展**
   - `apply_effects`：按 `sourceKind=synergy/sourceId/activationLevel` 挂载结构化效果。
   - `remove_source`：按 `sourceId` 精确移除该羁绊的全部修改器。
   - 完成后使受影响神将的 `modifierVersion + 1`，并按继承白名单刷新召唤物。

4. **首个后羿切片适配：已接入**
   - `toHeroV1GeneralStatModifiers(...)` 将月宫旧侣的成员属性效果投影为 `hero-v1/GeneralStatModifier[]`。
   - 遇到 `hero-v1` 尚不支持的目标范围、属性或效果类型时必须显式报错，不允许静默忽略。

5. **事件和快照：已接入**
   - 主链新增 `SYNERGY_ACTIVATED` / `SYNERGY_DEACTIVATED` / `SYNERGY_LEVEL_CHANGED`。
   - 玩家公开快照至少包含 `synergyId/displayName/level/contributingGeneralIds`。
   - 断线恢复后用棋盘投影重算并校验，不盲信客户端上报的激活羁绊。

## 9. 可测试验收项

### 9.1 纯羁绊内核

1. 棋盘上只有已组成后羿时，月宫旧侣不激活。
2. 同一玩家棋盘上后羿与嫦娥都已组成时，激活且只激活 1 次。
3. 嫦娥在托盘、备战席或属于其他玩家时，均不激活。
4. 固定/解除固定后激活集合完全一致。
5. 拆开嫦娥任意一字时，只产生一个 `remove_source(moon_palace_companions)`。
6. 异常输入两个同名后羿投影时，`Set<generalId>` 去重，不能满足“两名物理将”。
7. 阵营、职业、流派、命名集合和特定组合条件分别使用对应维度，不会因同名字符串跨维度命中。

### 9.2 属性与上限

1. 1 级后羿激活后射程从 3000 精确变为 3500 milli-cells。
2. 1 级后羿激活后攻击间隔从 1350ms 变为 1228ms，重连和回放结果一致。
3. 两个同层 `add_ratio` 以基点先求和；1000 与 1500 叠加后精确为 25%。
4. 多来源常驻减 CD 超过 4000 基点时截断为 40%，最终 CD 不低于 1000ms。
5. 羁绊失效后后羿恢复无羁绊数值，其他羁绊、武器和道具来源不被误删。

### 9.3 召唤物与工程性

1. 召唤物只继承模板白名单中的属性，未列出的后羿/嫦娥射程不会泄漏给召唤物。
2. 羁绊启停使存活召唤物按 `modifierVersion` 重算一次，不每 Tick 全量重算。
3. 配置中出现未知神将、重复羁绊 ID、重复激活层级或非法字数时，启动校验明确报错。
4. 相同棋盘投影、相同配置与相同操作序列得到字节级一致的激活集合和增量命令。
