# AgensTD 塔防竞品与玩家体验顶层升级规划

> 调研日期：2026-08-25  
> 范围：只讨论视觉、UI、交互、战斗反馈、节奏与结算体验；不修改现有服务端权威玩法规则，不在本文件内给出最终经济数值。  
> 证据标注：`[事实]` 表示来源页面明确描述或官方商店截图可直接观察；`[推断]` 表示基于竞品事实和本项目约束做出的设计判断。引用均为截至调研日可访问页面。

## 0. 先给结论

AgensTD 不应该被升级成另一款“买塔—点升级—看怪走路”的塔防。仓库中最有辨识度、也最值得放大的，是四个已经存在的核心：**汉字即单位、两两合兵、连续成神将、多人共享环形战场**。竞品真正值得学习的不是皮肤，而是三种能力：

1. 像《Bloons TD 6》《保卫萝卜4》一样，让玩家在首屏 3 秒内感到“角色正在活着、世界正在发生事情”；
2. 像《Kingdom Rush》《明日方舟》一样，让建造、攻击范围、技能目标和危险来源一眼可读；
3. 像《Rush Royale》《Random Dice》一样，把召唤、合成、波次和 Boss 压缩成连续、短反馈、可复玩的节奏，同时避免随机合成反噬玩家决策。

本项目的升级方向应概括为：**让字活起来、让因果看得见、让每局像一回西游章回**。

## 1. 本项目现状与不可变约束

以下判断来自仓库现有权威文档和前端实现，不是竞品推测：

- 《新版游戏总体架构及设计思路》定义了 29×29 棋盘、5 格召唤托盘、2 格备战席、刀/枪/弓/骑两两合成、连续汉字组成神将、最多 4 人共享波次与路线、服务端权威 Tick。
- 当前 `gaming-page.tsx` 是“左侧召唤/道具/对象信息 + 中央方形 Phaser 战场 + 右侧状态/Boss/羁绊/事件/提示”的三栏结构。重要战斗信息被拆散在多个可滚动卡片中。
- 当前 `battlefield-scene.ts` 已能渲染地形、单位字形、等级、敌人血条、状态字、Boss 徽标、效果区域和 220ms 位移补间，但尚没有攻击前摇、弹道、命中、受击、死亡、合成、成将和技能演出链。
- 协议和页面已经拥有 `BOSS_SPAWNED`、`BOSS_CAST_WARNING`、`BOSS_PHASE_CHANGED`、`GENERAL_SKILL_CAST`、`STATUS_APPLIED`、召唤物、效果区等表现数据。因此首轮升级应先消费现有事件，而不是先重做战斗协议。
- 当前移动端在 768px 以下把三栏纵向堆叠；储物区主要依赖 HTML `draggable/dataTransfer`。29 格在 390px 宽屏上单格约 13px，无法成为可靠触控目标。移动端需要独立的触控信息架构，不能只是桌面版缩放。
- 当前结算只有“胜/负标题 + 服务端结算提示 + 返回节点”，不能解释奖励、关键决策、进度或下一目标。

## 3. 可借鉴与不可照搬

### 3.1 必须借鉴的模式

1. **首屏先卖幻想，再卖规则。** BTD6、Kingdom Rush 和保卫萝卜都让地图、角色、敌人先说话。AgensTD 进入关卡时应用 1.5–2.5 秒可跳过章回开场：毛笔划出主路径，关卡题签盖印，镜头掠过出生门和 Boss 剪影，然后立即把控制权交给玩家。
2. **HUD 只常驻“此刻会改变决定”的信息。** 波次、容量危机、斋饭、人口、Boss/下波倒计时常驻；关卡说明、持续状态列表、事件日志、五维属性改为按需展开。
3. **空间上的事，在空间上解释。** 放置合法性、射程、穿透线、群攻圆、Boss 目标区、神将组合范围都在棋盘上显示；左右栏只显示详细数字。Kingdom Rush 的就地操作与明日方舟的范围覆盖均证明这种分层更快。
4. **高频动作短、重大事件长。** 召唤/拖放/普通攻击的确认应在 80–250ms 内完成；合成、成将、Boss 入场、Boss 转阶段、通关可以占用 0.6–2.0 秒，但都必须可跳过或不阻塞服务端状态。
5. **Boss 预警同时给“是什么、何时发生、打哪里、怎么躲”。** Rush Royale 用单位头顶手势标记被影响目标，BTD6 用血条刻度呈现阶段阈值。本项目已有施法目标与执行 Tick，应同时生成顶栏技能名、倒计时环、地图范围和目标字标记。
6. **结算必须解释本局。** 展示关键统计、首次达成、奖励来源、成长条和明确的“下一关/再来一局/返回”。单纯弹出“任务完成”会浪费最强情绪窗口。
7. **把可爱或酷建立在运动规律，不只建立在资源精度。** Battle Cats 的低帧夸张前摇说明，即使首批只有汉字和简单粒子，也能用 anticipation、overshoot、hit-stop、残影和音效做出角色感。

### 3.2 明确不可照搬

1. **不照搬 BTD6 的巨量升级树。** 它会与天兵 1–5 级、21 神将、22 羁绊、武器、道具争夺认知预算。
2. **不照搬 Kingdom Rush 的固定塔坑。** 本项目的价值在自由排字和连续组合；固定塔坑会破坏“汉字句法”。
3. **不照搬明日方舟的全员手动技能。** 神将已经规定自动施法；若再把 10+ 技能按钮交给玩家，4 人实时共享战场将演变成 UI 操作考试。
4. **不照搬 Rush Royale/Random Dice 的随机合并结果。** 玩家已经要应对召唤字池，合兵再随机会让神将配方、站位和羁绊失去可规划性。
5. **不照搬 Battle Cats 的横向单线。** 共享环路与跨区协防是当前多人差异点，应保留并把队友救场可视化。
6. **不照搬保卫萝卜“每主题大量新炮塔 + 大量一次性美术”的更新模式。** 应优先建立可复用的“字形动作语法、关卡调色、天气、机关与章回事件”生产管线。
7. **不以全屏粒子掩盖数值问题。** 每个特效都必须能回答“谁打的、打到谁、造成什么状态”；持续特效不能遮住路线、血条和 Boss 预警。

## 4. 三个创新体验支柱

### 支柱 A：字有兵魂——汉字不是图标，而是表演者

**体验承诺：** 不看面板，玩家也能通过笔画动作识别单位类别与攻击结果。

- 刀：横/撇笔锋蓄力，弧形斩痕，单体命中有短促顿帧。
- 枪：字身先压后刺，细长墨线穿透多个目标，被穿透目标按先后产生墨点。
- 弓：弧线拉伸，箭矢沿抛物线/直线飞行，暴击时“弓”字短暂开张。
- 骑：字向攻击方向倾斜并留双层残影，落点扩散马蹄形冲击波。
- 神将成形：相邻字符先被金线/朱砂顺序连读，正确组合后“题签盖印”，再释放 0.8 秒身份揭晓；重复观看可缩短到 0.35 秒。
- 羁绊激活：不再只在右栏新增一行文字，而是在相关神将之间走一遍可追踪的连线，随后缩成战场边缘的小徽记。
- 敌人死亡：按伤害属性使用“碎墨、燃纸、冰裂、雷灼”等 3–4 套可复用死亡语法；Boss 不直接消失，而是退印、裂字、散页。

**创新点：** 竞品通常用角色模型区分塔；AgensTD 用“字的笔势与成词关系”表达职业和组合。这既能降低 21 套全骨骼动画成本，也能形成无法被普通塔防复制的品牌资产。

### 支柱 B：因果可见——所有策略反馈都能从源头追到结果

**体验承诺：** 玩家失败时知道为什么，成功时知道是哪项决策生效。

- 选中单位：只显示其射程/形状、当前目标、伤害类型和下一次攻击节拍；详细五维下沉到二级卡。
- 拖动/点选放置：合法格青绿吸附，不合法格朱红叉；若可合成，目标字提前显示“Lv.+1”幽灵结果；若会成将，沿字符顺序显示配方预览。
- 伤害：普通伤害只在关键目标/低频采样显示；暴击、破甲、控制、Boss 抗性使用固定颜色和短标签。避免每 Tick 飘字。
- 协防：跨路击杀时由攻击者位置到目标闪过一次队友色轨迹，并在路线主人 HUD 上显示“P2 援护 +1”，把多人价值变成可感知事件。
- Boss：三段预警——远期 3–5 秒“技能名 + 目标”黄条；中期 1–2 秒地图范围增强；最后 0.35 秒红色收束与音效，执行后立即显示结果/抵抗。
- 结算：把“神将/羁绊/道具 → 关键贡献 → 奖励/解锁”串成一条因果链，不把奖励当孤立宝箱。

**创新点：** 利用服务端已有事件和稳定 Tick 做“可回放的因果动画”。同一事件既驱动即时表现，也能成为结算高光和 Bug 重现依据。

### 支柱 C：一局一章回——用戏剧节奏代替无差别刷怪

**体验承诺：** 20 波不是 20 次同样的加血，而是一回有起承转合的西游故事。

- **起（1–4 波）**：每波只引入一个可读问题；第 1 波完成“召唤—部署—首杀”，第 2–3 波引出合成/射程，第 4 波用短静默和环境变化预告首领。
- **承（5–9 波）**：第 5 波小 Boss；随后让新神将/羁绊有显著展示窗口，而不是马上用血量抹平成长。
- **转（10–15 波）**：第 10 波 Boss 改变局面；第 11 波的“需要神将”应表现为清楚的抗性/机制门槛，而不是无提示血量断崖。第 15 波检验构筑协同。
- **合（16–20 波）**：加快普通波间隔、减少低价值演出，把预算留给第 20 波多阶段 Boss、队友救场和通关印章。
- 波前 4–6 秒显示下一波 2–3 个关键敌人图标和一句反制提示；多人不允许暂停时，也要让征兵/调整动作在波间自然发生。
- 首次挑战保留完整章回演出；重复挑战自动缩短非交互动画，熟练玩家可选择“紧凑演出”，但不能改变服务端速度或竞技公平。

**创新点：** 用章回标题、题签、关卡字池和 Boss 技能把相同战场系统包装成戏剧段落，以较低美术成本制造“下一关想看什么”的期待。

## 5. UI 信息架构

### 5.1 战斗界面：从三栏仪表盘改为“战场中心 + 四条边缘控制”

```text
┌ 返回/连接 ─ 波次进度·下波敌人 ─ 容量危机 ─ Boss血条/施法 ┐  顶层：全局紧急信息
│                                                        │
│  P1队友状态                                  选中对象  │
│                                                        │
│                   29×29 战 场                          │  中层：空间决策与表现
│                                                        │
│  P2/P3/P4援护提示                           事件吐司   │
│                                                        │
├ 斋饭·人口 ─ 5格召唤托盘 ─ 2格备战 ─ 主动道具 ─ 召唤 ┤  底层：高频动作
└ 可展开抽屉：羁绊 / 详细属性 / 状态 / 战斗日志 / 关卡规则 ┘  深层：按需查询
```

**常驻层（玩家每 1–3 秒会看）：**

- 当前/总波次、下波倒计时和敌人预览；
- 容量 `当前/上限`，达到 70% 才强化颜色，90% 进入危机动画；
- 斋饭、下一次召唤成本、人口；
- 5 格托盘、2 格备战、召唤按钮、2 个主动道具；
- Boss 在场时占据顶部中央长血条，显示阶段刻度和施法倒计时。

**上下文层（选中后出现）：**

- 单位：名称/等级、攻击形状、当前目标、升级或成将预览；
- 神将：技能就绪环、固定/解除、相关羁绊；
- 敌人：护甲/魔抗/控制抗性、当前状态、Boss 技能说明；
- 格子：合法性、落点占用、会触发的组合变化。

**按需层：** 五维数值、全羁绊列表、状态实例、最近事件 Tick、关卡描述、协议错误。它们不能与召唤按钮争夺首屏面积。

### 5.2 开局与结算信息架构

**开局（最长 2.5 秒，可 1 秒后跳过）：**

1. 关卡章回标题 + 难度 + 1 句目标；
2. 路径被毛笔描出，出生门/P1–P4 标记亮起；
3. 首波敌人剪影和 Boss 伏笔；
4. 镜头回到玩家区，召唤按钮呼吸一次，控制权交还。

**结算（先情绪、后事实、再下一步）：**

1. 200–300ms 战场定格，胜利盖印/失败裂印；
2. 标题与结果原因；
3. 本局摘要：最高波、Boss、击杀、援护、最佳神将/羁绊、关键事件；
4. 奖励逐项飞入：金币、碎片、购买权，明确来源档位和是否首次；
5. 局外成长条/新解锁；
6. `下一关`（主按钮）、`再来一局`、`返回节点`。奖励演出 1.2 秒后可“全部展示”。

### 5.3 桌面、平板、手机三套外壳

- **桌面 ≥1280px：** 中央战场至少占短边 72%；托盘移到底部，不再把召唤和选中对象挤在窄左栏；右侧只保留可折叠上下文卡。
- **平板/横屏 768–1279px：** 战场占 68–75%，顶栏与底部 Dock 固定，详细信息从右侧浮层进入；不发生整页滚动。
- **手机竖屏 320–767px：** 战场方形置于上方约 52–58dvh，顶部只留波次/危机/Boss；底部为拇指操作 Dock，上滑打开托盘/备战/道具，下滑收起；对象详情为半高 Bottom Sheet。
- 手机端部署采用“点卡 → 棋盘显示可放格 → 点落点 → 幽灵预览 → 确认/再次点确认”，同时支持拖放，但不能只依赖 HTML `dataTransfer`。
- 棋盘格物理上无法同时达到大触控目标：允许双指缩放/拖动画布、边缘自动平移、临近合法格磁吸、长按放大镜；密集地图格可使用 WCAG 的 essential 例外，但高频按钮仍以 44×44 CSS px 为目标。W3C 的 AA 最低为 24×24，AAA 增强目标为 44×44。[WCAG 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) / [WCAG 2.5.5](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced)

## 6. 动画与反馈层级

### 6.1 五级预算

| 层级 | 使用场景 | 视觉/声音预算 | 约束 |
|---|---|---|---|
| L0 环境 | 路径微光、云雾、旗幡、出生门呼吸 | 低频循环、无强闪、几乎无音效 | 同屏始终存在，但不能抢目标注意力 |
| L1 操作确认 | hover/按下、卡片选中、合法格、拖放、召唤扣费 | 80–180ms，1 个色块/音符 | 本地立即响应，不等待服务端往返；失败后回弹并解释原因 |
| L2 常规战斗 | 普攻前摇、弹道、命中、普通死亡 | 单次 180–450ms；小粒子可池化 | 同屏过多时合批、采样飘字、自动降粒子 |
| L3 战术事件 | 合成、成将、羁绊、主动道具、暴击、清波 | 0.35–0.9s；局部慢动作/音色主题 | 不遮住 Boss 预警；重复事件自动缩短 |
| L4 高潮 | Boss 入场/转阶段/死亡、失败危机、通关 | 0.8–2.0s；镜头、题签、音乐段落 | 可跳过或非阻塞；多人状态继续按服务端 Tick 运行 |

### 6.2 一次攻击的标准反馈链

```text
服务端事件到达
  → 找到 source/target 与事件发生 Tick
  → 若事件已过时，缩短或直接播放命中结果
  → 前摇姿态（90–160ms）
  → 弹道/连线（按距离 80–300ms）
  → 命中闪 + 受击位移/缩放（60–120ms）
  → 血条追随条在 160–260ms 内结算
  → 关键伤害/状态标签
  → 死亡或阶段事件提升到 L3/L4
```

- 服务端伤害仍然先结算；动画不能阻塞状态，也不能制造“命中前敌人已死却仍停留”的幽灵。
- 利用现有 `tickRateMs=100` 与事件 Tick 做追帧；220ms 移动补间应与攻击表现解耦。
- 普通伤害数字只展示暴击、击杀、Boss、玩家选中目标或每 300ms 聚合值；其余由血条与受击反馈表达。
- 屏幕震动只用于 L4 或重型命中，默认 2–5px、80–160ms；提供“减少动态效果”。浏览器可通过 `prefers-reduced-motion` 响应系统设置。[MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion)

### 6.3 色彩与声音语法

- 物理：米白/金属灰 + 短促木石音；魔法：青紫 + 延音；治疗/增益：翠绿；危险/Boss：朱红；可交互/合法：青绿；资源：稻金。
- 颜色不单独承担语义：危险同时使用图形收束、倒计时与音效；状态同时有汉字短标签。
- 每类天兵有独立的前摇节奏与命中音，不要求首期做 21 套完全不同的动画。神将首期用“职业基底 + 品质层 + 专属题签/技能关键帧”组合生产。
- 音效优先级为 Boss 预警 > 玩家主动操作 > 成将/羁绊 > 击杀 > 普攻；高密度普攻做并发上限和音量侧链，避免噪声墙。

### P2：内容化、社交化与长期优化

- 关卡级调色/天气/题签/Boss 入场模板；
- 多人援护轨迹、救场/让刀/最快清路结算称号；
- 可分享的 8–12 秒结算高光；
- 外观只改变字体皮肤、笔锋、命中特效、题签和音乐，不改变命中框或预警可读性；
- 基于遥测自动调低高密度特效，并对不同设备保存表现档位；
- A/B 测试首屏、召唤按钮、下波预览和结算 CTA，指标看首局完成率、第二局开启率、误操作率，而非只看点击量。

## 8. 平衡与体验联动指标（不给最终数值，但先定义仪表盘）

视觉升级不能掩盖数值问题。数值团队至少应按难度、关卡、玩家数和构筑记录：

- 每波清理时长、中位存活怪数、容量 ≥70%/90% 的持续时间；
- 第一次召唤、第一次部署、第一次合成、第一次成将的发生时间；
- 每分钟斋饭收入/支出、召唤次数、空托盘时间、满人口时间；
- 各天兵有效 DPS、有效开火占比、溢出伤害、群攻实际命中数；
- 各神将技能有效命中、控制有效时长、经验/分钟、羁绊激活波次；
- Boss 每技能命中人数、预警到响应时间、阶段死亡率；
- 失败原因分布：容量、Boss 技能、经济断档、错误布局、断线/输入失败；
- 首局通关率、首局完成率、第二局开启率、次日回访；
- 结算页停留、跳过、下一关/再来/返回比例。

首轮体验目标建议：简单难度首关完成率 85–95%，但“无神将纯天兵”进入中期后应清楚遇到机制门槛；首局中至少让 80% 玩家经历一次合成升级，60% 经历一次成将或明确看到成将进度，100% 看见一次可理解的 Boss 预警。

## 9. 风险与守门规则

1. **表现与权威状态脱节：** 所有动画都从事件/快照派生，动画状态不能反写战斗结算。
2. **信息越做越多：** 新增任何常驻 HUD 元素时必须删除或下沉一个同级元素；常驻层只允许 5 类全局信息。
3. **手机端把棋盘缩没：** 禁止以三栏纵向堆叠作为“响应式完成”；必须以核心任务真机验收。
4. **特效影响反应：** Boss 预警使用独立最高层；任何粒子、成将遮罩和结算预演都不得覆盖它。
5. **性能预算失控：** 使用对象池、合批、粒子上限和设备档位；浏览器动画按刷新周期驱动，后台页暂停非关键表现。`requestAnimationFrame` 通常跟随显示器刷新率，后台标签会暂停以节省资源。[MDN](https://developer.mozilla.org/en-US/docs/Web/API/window/requestAnimationFrame.)
6. **随机挫败被误当“刺激”：** 召唤概率、首抽安全修正和供应耗尽需要可解释；合成结果保持确定性。
7. **结算数字与服务端不一致：** 奖励动画只消费服务端结算清单，客户端不得重算档位或提前发奖。

## 10. 建议的模块化交付顺序

1. **体验总监/产品子代理：** 锁定三支柱、界面状态图、常驻信息上限和跨端任务流。
2. **战斗表现子代理：** 建立事件到动画的表现规范与性能预算，先完成四天兵纵向切片。
3. **UI/交互子代理：** 重构桌面/平板/手机三套外壳，完成放置、合成、选中、Boss 预警原型。
4. **Boss/关卡导演子代理：** 为 5/10/15/20 波制作预警、入场、阶段和章回节奏表。
5. **结算/奖励子代理：** 设计服务端奖励清单的呈现、成长反馈与下一步 CTA。
6. **数值/遥测子代理：** 用真实路径模拟与局内遥测校准波次、经济、天兵、神将、Boss。
7. **QA/性能/可访问性子代理：** 建立跨端输入矩阵、视觉回归、断线追帧、低端性能和减少动态测试。

每个子代理都应交付“可运行纵向切片 + 指标面板 + 回归用例”，不得只交静态视觉稿。P0 完成前，不建议并行量产 21 套专属动画；先证明事件底座、四兵种语法、Boss 预警与跨端 HUD 能稳定运行。
