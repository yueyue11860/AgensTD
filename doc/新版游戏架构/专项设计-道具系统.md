> 状态：V1.0 可开发设计稿
>
> 适用范围：PVE、局外永久道具、2 个主动槽、6 个被动槽、主动道具手动使用、被动道具开局生效、购买权、服务端动作与回放
>
> 关联文档：《总体架构及设计思路.md》《征兵与棋盘交互架构.md》《神将体系架构》《专项设计-统一效果系统.md》《专项设计-局外结算与购买权.md》

## 一、设计目标与锁定结论

道具负责“玩家整局构筑”和“关键时刻的手动决策”：

- 主动道具由玩家在局内点击并选择目标；
- 被动道具在开局自动改变携带者自己的经济、征兵、人口、成长、战斗或掉落规则；
- 神将主动技能仍由系统自动释放，不属于主动道具；
- 武器属于具体神将，道具默认属于玩家整局，两者作用域必须分开。

首版锁定：

1. 每名玩家携带 2 件主动道具、6 件被动道具，槽位允许为空。
2. 同一 `itemId` 不能重复携带；主动与被动 ID 全局唯一。
3. 道具在局外永久解锁，不是用一次就从账户消失的消耗品。
4. 主动道具的局内次数和 CD 每局重置；被动道具每局重新挂载。
5. 局外构筑在玩家加入房间时生成不可变快照；局内不能更换。
6. 主动道具默认只操作携带者自己的棋子、托盘、备战席、神将进度，或对当前可攻击敌人产生效果；首发目录不包含直接操作队友单位的道具。
7. 被动道具的“全局”默认是 `owner_global`，只影响携带者，不自动共享给其他玩家。
8. 新版没有扩地操作，任何道具都不能增加、解锁或改变棋盘地块。
9. 改字、找回字符、托盘刷新等状态结构变化走注册规则动作；战斗属性和状态走统一效果系统。
10. 下文数值是首轮联调基准，ID、目标、生命周期、作用域、失败消耗规则属于结构性结论。
11. 首发目录固定为 8 件主动道具、15 件被动道具；后续新增道具必须复用同一 schema、动作注册表和效果预算。

首版不做：PVP 道具、道具品质、道具升级/碎片、随机词条、每日清空、赛季轮换、交易、赠送、队友棋子强制操作、向其他玩家投放负面效果以及脚本型 `custom` 道具。

## 二、账户、携带与开局快照

### 2.1 永久账户

```ts
interface PlayerItemAccount {
  playerId: string
  unlockedActiveItemIds: string[]
  unlockedPassiveItemIds: string[]
  loadout: {
    activeSlots: [string | null, string | null]
    passiveSlots: [
      string | null,
      string | null,
      string | null,
      string | null,
      string | null,
      string | null
    ]
    version: number
    updatedAt: string
  }
  version: number
}
```

首版新账户免费解锁：

- 主动：`change_character_brush` 点将笔、`cultivation_pill` 修为丹；
- 被动：`traveling_kitchen` 行军灶、`talent_registry` 招贤榜、`reserve_expansion_talisman` 备战符。

免费包确保新玩家可以立即体验改字、神将成长、经济、找字和换阵空间，其他道具通过购买权逐步解锁。

### 2.2 携带规则

保存 `SAVE_ITEM_LOADOUT` 时服务端校验：

1. 槽位数量严格为 2 与 6；
2. 道具定义存在且类型与槽位一致；
3. 玩家已经永久解锁；
4. 所有非空 `itemId` 不重复；
5. 没有违反定义中的 `exclusiveGroup`；
6. `expectedLoadoutVersion` 与当前版本一致。

首版只设置两个互斥组：

- `character_probability`：未来新增多个字符概率被动时，同一构筑最多携带 1 个；
- `boss_fragment_bonus`：未来新增多个额外掉落被动时，同一构筑最多携带 1 个。

`求贤令` 属于保底规则，不属于概率加成，可以与 `招贤榜` 同时携带。

### 2.3 对局快照

```ts
interface MatchItemLoadoutSnapshot {
  snapshotVersion: 1
  playerId: string
  accountVersion: number
  activeItems: readonly ResolvedActiveItemDefinition[]
  passiveItems: readonly ResolvedPassiveItemDefinition[]
}
```

- 加入房间并锁定构筑时由服务端生成；
- 房间开始后不可修改；
- 断线重连恢复同一快照、次数、CD、计数器和监听器；
- 玩家永久退出时注销其被动监听器，已经结算的永久奖励不回滚；
- 局外随后保存的新方案只影响下一局。

## 三、道具定义与运行时状态

### 3.1 通用定义

```ts
interface ItemDefinitionBase {
  schemaVersion: 1
  itemId: string
  name: string
  itemKind: 'active' | 'passive'
  exclusiveGroup?: string
  tags: string[]
  ui: {
    shortDescription: string
    detailDescription: string
    iconKey: string
  }
  status: 'prototype' | 'testing' | 'released'
}
```

### 3.2 主动道具

```ts
interface ActiveItemDefinition extends ItemDefinitionBase {
  itemKind: 'active'
  availabilityPhases: Array<'prep' | 'spawning' | 'clearing'>
  targeting: ActiveItemTargeting
  maxChargesPerMatch: number
  cooldownMs: number
  effects: StructuredEffect[]
  actions: RegisteredRuleAction[]
  failurePolicy: 'no_consume'
}

interface ActiveItemRuntimeState {
  itemId: string
  slotIndex: 0 | 1
  chargesRemaining: number
  cooldownEndsAtTick: number
  usesThisMatch: number
  enabled: boolean
}
```

CD 从服务端确认成功的 Tick 开始，在 `prep`、`spawning` 和 `clearing` 阶段都正常流逝。次数为 0 时永久禁用到本局结束；`idle` 与 `complete` 阶段不能使用。

### 3.3 被动道具

```ts
interface PassiveItemDefinition extends ItemDefinitionBase {
  itemKind: 'passive'
  scope: 'owner_global' | 'team_global'
  attachAt: 'player_match_state_initialized'
  effects: StructuredEffect[]
  ruleModifiers: RegisteredRuleModifier[]
  eventListeners: RegisteredItemListener[]
  stacking: {
    group: string
    policy: 'unique' | 'highest' | 'additive'
  }
}
```

首发目录全部为 `owner_global`。`team_global` 只保留数据能力，不在首发道具中使用，避免多人重复叠加和强制队友围绕某件道具构筑。

## 四、主动道具使用协议

### 4.1 权威流程

```text
玩家点击主动道具
→ 客户端只进入目标预览
→ 玩家确认后发送 USE_ACTIVE_ITEM
→ 服务端按 requestId 去重
→ 校验快照、槽位、次数、CD、阶段、目标和状态版本
→ 在单个权威 Tick 内执行动作/效果
→ 成功后扣 1 次并开始 CD
→ 广播 ITEM_USED 与产生的规则/战斗事件
```

取消目标选择不会发送命令。校验失败、目标在确认前消失、版本过期或效果没有任何合法目标时，默认不扣次数、不进入 CD。

### 4.2 命令

```ts
interface UseActiveItemCommand {
  type: 'USE_ACTIVE_ITEM'
  requestId: string
  playerId: string
  slotIndex: 0 | 1
  itemId: string
  target:
    | { kind: 'none' }
    | { kind: 'tile'; zone: 'summon_tray' | 'reserve' | 'board'; index?: number; x?: number; y?: number }
    | { kind: 'piece'; pieceId: string; expectedRevision: number }
    | { kind: 'general'; generalId: string }
    | { kind: 'enemy'; enemyId: string }
    | { kind: 'battlefield_point'; xMilli: number; yMilli: number }
  expectedItemRuntimeVersion: number
}
```

客户端不能提交伤害、经验、替换结果或随机候选，只提交意图和目标。

### 4.3 执行顺序

同一 Tick 多名玩家使用主动道具时按服务端动作序列号结算。每条命令完成后立即提交新状态，下一条命令看到的是最新结果；不会让两个请求同时占用同一个字符 Token、弃置 Token 或棋盘单位。

## 五、注册规则动作

改变棋盘、字符池或玩家规则的能力不能伪装成战斗效果。首批动作：

| 动作 | 权威写入 | 核心校验 |
| --- | --- | --- |
| `replace_character_token` | 替换一个现存字符 Token 的 glyph/recipeCandidates | 所有权、区域、未固定、剩余字符候选 |
| `grant_general_experience` | `generalProgressById` | 神将存在、未达当前等级上限 |
| `grant_general_level` | 补足到下一等级的经验 | 当前上限、单次只升 1 级 |
| `refresh_summon_tray` | 原子弃置旧托盘并生成 5 个新结果 | 托盘版本、有限字符池、征兵锁 |
| `recover_discarded_character` | 弃置区 Token 转入空托盘/备战位 | Token 仍在弃置区、目标为空 |
| `modify_recruit_rule` | 玩家征兵规则快照 | 最低费用、概率与有限 Token 边界 |
| `modify_population_cap` | 玩家人口上限 | 不改变棋盘面积 |
| `modify_reserve_capacity` | 备战席容量 | UI 与协议容量一致 |
| `modify_fragment_drop_profile` | 玩家个人 Boss 掉落 profile | 不直接写永久账户 |

所有动作需要独立 schema、错误码、事件和 smoke；不存在 `expand_board`。

## 六、首发主动道具目录

### 6.1 点将笔

| 字段 | 设计 |
| --- | --- |
| ID | `change_character_brush` |
| 次数 / CD | 2 次 / 15 秒 |
| 可用阶段 | `prep`、`spawning`、`clearing` |
| 目标 | 自己召唤托盘、备战席或棋盘中的单个字符 |
| 效果 | 将目标字符改为“当前大本营仍剩余的其他神将字符”之一，位置不变 |

## 八、求贤令、字符池和第一批召唤的精确顺序

每次付费召唤按以下顺序生成：

1. 读取剩余字符 Token；
2. 每个槽按当前字符概率做分支，命中后从剩余 Token 等权抽取；
3. 如果是玩家本局第一批且五格全为字符，把一个槽回退并生成随机天兵，保证至少 1 个天兵；
4. 如果携带求贤令且本次是保底批、当前仍无字符且尚有剩余 Token，从非强制天兵槽中选 1 格改为字符；
5. 一次性提交 5 个结果与 Token 流转；
6. 本批有字符则 `noCharacterPaidBatchStreak = 0`，否则加 1；
7. 增加付费召唤次数并计算下一次 5、7、9……费用。

该顺序保证招贤榜、求贤令和首批天兵保护不会互相覆盖或复制 Token。

## 九、效果、来源与贡献归属

### 9.1 来源键

```text
passive_item:{matchId}:{playerId}:{slotIndex}:{itemId}:{effectId}
active_item:{matchId}:{playerId}:{slotIndex}:{itemId}:{useSequence}:{effectId}
```

被动来源从开局挂载到玩家永久退出/结算结束。主动来源按持续时间独立存在；相同主动再次使用时按效果自己的 `stackGroup` 处理。

### 9.2 与神将、武器和羁绊

- 被动道具与武器、羁绊修改相同属性时进入统一结算层，不直接覆盖其他来源；
- 主动道具给神将经验或等级时写 `generalProgressById`，不是汉字 Token；
- 神将拆合不能重置主动增益、道具次数、CD 或求贤计数；
- 道具不能在局内换武器，也不能绕过武器适配、双槽和专属限制；
- 召唤物是否受被动道具影响必须显式指定 `summon_owned_by_player`，不能从“全局攻击”猜测；
- 道具伤害/控制不归属神将，不产生神将经验资格；
- 由被动增益后的神将或召唤物正常造成伤害时，贡献仍归对应神将。

### 9.3 上限

道具不能突破：

- 最终攻速 5 次/秒；
- 常驻冷却缩减 40%；
- 普通怪/Boss 最低移速；
- 硬控递减和单次时长上限；
- 全伤易损上限；
- 路径位移上限；
- 召唤存活数量和效果事件预算。

## 十、多人 PVE 与反恶意规则

1. 每位玩家拥有独立的主动次数、CD、被动来源、求贤计数和掉落加成。
2. 首发被动全部是 `owner_global`，不会因为四人携带同名道具而叠到全队。
3. 点将笔、修为丹、神将符、再征令、招魂幡、战鼓令只能操作自己的状态。
4. 天雷令和定风符可以作用于当前战场中任意可攻击敌人，但不能作用于出生保护怪物。
5. 主动道具不能移动、删除、改字或升级队友棋子，避免误操作与恶意破坏。
6. 玩家永久退出后不能继续使用道具；其被动监听器立即注销，已生成的限时战斗效果按定义自然结束或移除。
7. 同一 Tick 的并发请求进入同一权威动作队列，不采用客户端先到先改本地状态。

## 十一、购买权与永久解锁

《专项设计-局外结算与购买权.md》中的：

- `passive_item` 购买权只生成未解锁被动道具；
- `active_item` 购买权只生成未解锁主动道具。

每张购买权生成 3 个固定候选，候选以 `entitlementId` 为种子，不因重复打开商店变化。成功购买任意 1 件后消耗购买权并永久解锁。

| 商品 | 首轮价格 |
| --- | ---: |
| 主动道具永久解锁 | 10 局外金币 |
| 被动道具永久解锁 | 10 局外金币 |

金币不足、取消购买、并发版本冲突或服务端失败不消耗购买权。某类别已经全部解锁时，购买权继续保留，不自动兑换、不丢失，等待后续目录扩充。

## 十三、前端页面与交互

### 13.1 局外道具构筑页

- 主动区固定显示 2 槽，被动区固定显示 6 槽；
- 道具卡显示类型、作用域、每局次数/CD 或常驻效果；
- 未解锁道具展示购买权入口；
- 冲突道具置灰并说明唯一组；
- 保存成功后显示版本号，版本冲突时重新拉取。

### 13.2 局内主动栏

- 显示 2 个主动按钮、剩余次数和 CD；
- 无合法目标、次数为 0 或 CD 中时置灰；
- 点击需要目标的道具后，高亮合法目标并显示取消；
- 客户端预览不改变状态，服务端确认后才播放正式效果；
- 重连后以服务端剩余 Tick 恢复 CD。

### 13.3 被动摘要

战场状态栏可以展开 6 个被动来源，显示已经实际结算的初始斋饭、召唤概率、人口、等级上限等，不只显示描述文本。

## 十五、验收清单

1. 局外只能保存 2 个主动、6 个被动，同一 ID 不重复。
2. 未解锁、类型错误、唯一组冲突和过期版本不能保存。
3. 开局后局外换装不影响当前局，重连保持同一快照。
4. 主动道具未携带、无次数、CD 中、阶段不符或目标非法时不消耗。
5. 同一 `requestId` 重放 100 次仍只执行一次、只扣一次次数。
6. 点将笔不复制 Token，固定神将未解除时不能改字，改后组合/人口/羁绊立即一致。
7. 再征令不扣斋饭、不增加付费召唤价格、不累计求贤令次数，但正常消耗有限字符。
8. 求贤令与 12% 招贤榜、首批至少 1 个天兵共同生效时结果仍确定且不复制字符。
9. 修为丹和神将符遵守当前等级上限；紫/橙突破只改上限、不直接升级。
10. 备战符只增加备战位，扩军令只增加人口，两者都不扩地。
11. 天雷令和定风符不能命中出生保护怪物；天雷令不能完成最后一击。
12. 被动只影响携带者，四名玩家携带同名道具不会叠成团队效果。
13. 神将拆合不能重置主动增益、道具 CD、次数、求贤计数或重复挂载被动。
14. 道具与武器、羁绊叠加后仍受攻速、冷却、控制、位移、易损和召唤预算限制。
15. 主动/被动购买权只在成功支付并永久解锁后消耗，重复购买不重复扣金币。
16. 同一种子、携带快照和操作序列能完整复现主动目标、随机改字、求贤保底和额外碎片。
