# Web 游戏卡顿彻底排查（2026-08-26）

## 结论

不需要更换游戏引擎。项目已使用 Phaser 4.2.1，当前卡顿的根因是对引擎的静态几何、快照和浏览器合成层使用不当，不是引擎能力不足。

Phaser 官方发布列表显示 4.2.1 是当前最新 Phaser 4 版本（2026-07-09）；官方 `Graphics.generateTexture` 也正是用于把复杂 Graphics 生成纹理的 API。

- Phaser 4 版本：https://phaser.io/download/phaser4
- Graphics.generateTexture：https://docs.phaser.io/api-documentation/4.0.0/class/gameobjects-graphics#generateTexture

## 根因与修复

1. 29×29 地形原来由 841 个圆角格子、描边和保护区 Graphics 组成，每帧都重复走几何渲染管线。现在创建场景时一次性烘焙为一张纹理，每帧只绘制一个 quad。
2. 鼠标在同一格内滑动时，每个 `pointermove` 都创建新坐标对象并触发整页 React 更新；内联构造的战场快照又让 Phaser 重算整个战场。现在按格子去重，快照使用 `useMemo`，Scene 也拒绝同一引用的重复快照。
3. 全屏噪点的 `mix-blend-mode` 和动态 Canvas 上的多层 `backdrop-filter` 强制浏览器每帧重新合成。实战页已去掉这些高成本效果，并对 Canvas 设置合成隔离。
4. 详细敌人是由 8 个 Graphics/Text 子对象组成的 Container。超过 8 个敌人时现在切换为预合成 Sprite，保留字形、职能、状态和血条信息，避免常规战斗中的对象膀胀。
5. 原验收门槛容许 20 FPS 和 55ms P95 帧时间，会把明显卡顿判为通过。现在收紧为软件渲染环境最低 50 FPS、P95 不超过 30ms、长任务必须为 0。
6. 怪物位置由 200ms 权威快照驱动，但客户端原来每次收到战斗事件也会杀掉并重开位置补间，即使坐标完全没变；不同怪物还使用 125–300ms 的非线性特效时长，造成“移动—停顿—追赶”。现在同目标不再重启，全部按快照 tick 间隔做线性插值，并保留 10% 网络抖动缓冲。
7. Phaser 原来启用 `roundPixels`。慢速怪物每帧位移不足 1 个世界像素，棋盘缩放后被量化成约 20 次可见跳动/秒。现在关闭整像素取整，位置在每个渲染帧按亚像素连续推进。

## 怪物移动连续性

服务端投影保留 `xMilli / 1000`、`yMilli / 1000` 的小数坐标，100ms 逻辑 tick 和 200ms 网络广播并没有丢失空间精度。问题完全发生在旧客户端表现层，因此无需提高服务端 tick 频率，也无需迁移引擎。

移动回归测试现在覆盖：同坐标事件不重启、200ms 快照对应 220ms 带缓冲插值、网络停顿时长封顶、每个亚像素帧都单调前进，以及无动画偏好下立即对齐。真实 Chromium 的 80 敌人压力场景末段为 62.5 FPS、P95 17.4ms、长任务 0。

## 同一验收脚本前后对比

| 场景 | 修复前 FPS | 修复后 FPS | 修复前 P95 | 修复后 P95 |
| --- | ---: | ---: | ---: | ---: |
| 部署后空场 | 24.6 | 103.4 | 42.6ms | 16.7ms |
| 高事件实战末段 | 21.8 | 53.3 | 50.1ms | 25.2ms |
| 80 敌人、338 批战斗事件 | 22.4 | 62.5 | 50.1ms | 17.4ms |

修复后 80 敌人压力场景持续 317,000ms 逻辑时间，长任务 0，堆内存增长约 9.1MB，桌面与 390px 移动视口均无溢出。最终报告位于 `output/playwright/production-experience-qa.json`。

后端在加速压力环境下平均 tick 约 0.7–2.5ms，峰值约 11.7ms，远低于 100ms 的逻辑 tick 间隔，不是本次卡顿主因。

## 引擎决策

保留 Phaser 4.2.1。更换 PixiJS、Three.js、Unity WebGL 或 Godot Web 都需要重写场景、输入、表现、音频和 React 桥接，而当前已证明 Phaser 在同一压力场景下可达 70 FPS 以上。当前投入应继续放在静态层烘焙、Sprite 批处理、快照去重和性能回归门槛，而不是引擎迁移。
