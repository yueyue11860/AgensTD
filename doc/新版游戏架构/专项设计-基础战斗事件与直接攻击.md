# 专项设计：基础战斗事件与直接攻击

> 状态：V0.1，第一版战斗内核  
> 目标：先完成“天兵自动攻击 → 小怪受伤 → 小怪死亡 → 奖励结算”

## 1. 第一版范围

包含：

- 物理、魔法两种直接伤害。
- 单体、直线穿透、目标点范围三种攻击形状。
- 服务端自动选敌。
- 普通攻击命中。
- 确定性暴击。
- 护甲、魔抗减伤。
- 小怪死亡、斋饭奖励、神将经验分配。

暂不包含：

- 命中率、闪避、格挡、无敌和护盾。
- 治疗、吸血、反伤、伤害转移。
- 独立飞行的弹道实体。
- 连锁、分裂、复杂技能触发器。
- 控制、易损、召唤物继承；这些在统一效果系统中逐项接入。

## 2. 确定性基础

- 战斗只由服务端 Tick 推进。
- 配置中的毫秒统一换算为 `ceil(milliseconds / tickDurationMs)` 个 Tick。
- 概率统一使用 0～10000 基点。
- 位置、路径、经验使用定点整数。
- 随机只使用 `matchSeed + eventSequence` 驱动的确定性 PRNG，禁止 `Math.random()`。
- 同 Tick 的攻击者稳定顺序：玩家加入序号、棋盘 Y、棋盘 X、`entityId`。

## 3. 攻击运行时

```ts
interface BasicAttackRuntime {
  attackerId: string;
  ownerPlayerId: string;
  damageType: 'physical' | 'magic';
  attackShape: 'single' | 'line_pierce' | 'radius';
  attack: number;
  rangeMilliCells: number;
  attackIntervalTicks: number;
  critChanceBps: number;
  critDamageBps: number;
  nextAttackTick: number;
}
```

第一版采用“服务器即时命中、客户端播放弹道表现”：

- 服务端在攻击 Tick 直接冻结目标并结算结果。
- 客户端可根据事件播放箭、刀光等动画，但弹道到达不能再次请求伤害。
- 若表现时间跨 Tick，客户端仍以服务端给出的 `hitTick` 和最终伤害为准。

## 4. 目标选择

### 4.1 射程

以棋盘中心点计算定点欧氏距离平方：

```text
distanceSquared <= rangeSquared
```

不要先开平方，避免浮点误差。

射程判断前先执行路线所有权过滤：

- 小怪处于 `private_lane` 时，只有 `attacker.ownerPlayerId = enemy.homeLanePlayerId` 才是合法目标。
- 小怪进入 `public_loop` 后，任意仍在对局中的玩家都可以攻击。
- 进入公共圈由服务端路径状态产生，客户端不能自行标记；全屏技能和召唤物默认也遵守该限制。

### 4.2 主目标稳定排序

从射程内且 `lifecycle = alive` 的小怪中依次比较：

1. 标准化后的 `threatProgressMilli` 大者优先；不能直接比较包含不同私有路线前缀的原始路径索引。
2. `spawnSequence` 小者优先。
3. `entityId` 字典序小者优先。

若没有合法目标，本 Tick 不攻击、也不消耗冷却。

`threatProgressMilli` 由地图快照计算：私有段使用本路线到公共入口的归一化进度；公共圈使用“私有段基准长度 + 圈数 × 公共圈长度 + 本圈进度”。这样 P1～P4 的不同前缀长度不会破坏稳定排序。

### 4.3 形状目标

- `single`：只有主目标。
- `line_pierce`：主目标加攻击者至主目标方向的直线命中集合，再按路径进度和 ID 排序，截取配置上限。
- `radius`：主目标加目标点半径内集合，再按路径进度和 ID 排序，截取配置上限。

攻击开始时冻结本次目标集合。后续同 Tick 的移动、死亡或其他攻击不能把新目标补进集合；已死亡目标直接跳过。

## 5. 暴击与伤害

每个目标单独产生一次暴击判定：

```text
isCritical = rng.nextInt(10000) < critChanceBps
rawDamage = attack
if isCritical:
  rawDamage = floor(rawDamage × critDamageBps / 10000)
```

物理伤害：

```text
finalDamage = floor(rawDamage × 100 / (100 + max(0, armor)))
```

魔法伤害：

```text
finalDamage = floor(rawDamage × 100 / (100 + max(0, magicResistance)))
```

只要 `rawDamage > 0`，最终伤害最低为 1。第一版不支持负护甲/负魔抗；后续易损使用独立乘区，不能偷偷写成负抗性。

## 6. 事件模型

```ts
type BasicCombatEvent =
  | BasicAttackStarted
  | BasicAttackHit
  | CriticalRolled
  | DamageApplied
  | EnemyDied
  | RiceGranted
  | LaneWaveCleared
  | GeneralXpDistributed;
```

最低事件字段：

| 事件 | 必要字段 |
|---|---|
| `BASIC_ATTACK_STARTED` | eventId, tick, attackerId, frozenTargetIds |
| `CRITICAL_ROLLED` | eventId, attackEventId, targetId, roll, threshold, isCritical |
| `BASIC_ATTACK_HIT` | eventId, attackEventId, attackerId, targetId |
| `DAMAGE_APPLIED` | eventId, sourceId, sourcePlayerId, targetId, damageType, rawDamage, finalDamage, hpBefore, hpAfter |
| `ENEMY_DIED` | eventId, enemyId, deathSettlementId, killerPlayerId, homeLanePlayerId |
| `RICE_GRANTED` | eventId, playerId, reason, enemyId/waveNumber, amount |
| `LANE_WAVE_CLEARED` | eventId, playerId, waveNumber, rewardRice |
| `GENERAL_XP_DISTRIBUTED` | eventId, enemyId, killerPlayerId, allocations |

事件是已经发生的事实；玩家动作是意图。客户端不得发送 `DAMAGE_APPLIED` 或 `ENEMY_DIED`。

## 7. Tick 阶段

同一 Tick 固定按以下顺序：

1. 接收并排序玩家动作。
2. 执行征兵、拖放、合成、固定等合法动作。
3. 生成波次小怪。
4. 推进小怪移动。
5. 更新已注册状态效果。
6. 收集到期的自动攻击。
7. 按稳定顺序选敌、暴击、伤害。
8. 统一处理死亡和奖励。
9. 更新各出生路线的本波存活计数并发放独立清波保底。
10. 移除死亡实例并检查超载/胜负。
11. 生成公开/私有状态补丁并记录回放。

同 Tick 中，一个较早攻击者击杀目标后，后续攻击者若冻结集合中只有该目标，则本次攻击落空，但冷却已消耗。这样不会因客户端顺序产生补选差异。

## 8. 冷却规则

- 部署、移动、交换或合成后，天兵需等待一个完整攻击间隔才可首次攻击。
- 成功开始攻击后设置 `nextAttackTick = currentTick + attackIntervalTicks`。
- 无目标时不修改 `nextAttackTick`，下个 Tick 可再次寻敌。
- 第一版不提供攻速上限、减冷却或冷却重置。

## 9. 神将贡献账本

虽然第一版先由天兵打怪，事件层必须预留神将经验账本：

```ts
type ContributionKind = 'physical' | 'magic' | 'summon' | 'control';

interface GeneralContributionEntry {
  enemyId: string;
  ownerPlayerId: string;
  generalProgressId: string;
  kind: ContributionKind;
  lastEffectiveTick: number;
}
```

- 只保留最近 5 秒的有效贡献。
- 伤害大于 0 记物理/魔法贡献。
- 召唤物伤害映射回所属神将，记召唤贡献。
- 减速、眩晕、易损实际生效才记控制贡献。
- 同一神将对同一怪物同一类别只保留一条记录。
- 小怪死亡时先读取最后一次有效伤害的 `sourcePlayerId` 作为 `killerPlayerId`。
- 只筛选 `ownerPlayerId = killerPlayerId` 的贡献记录；其他玩家的贡献不参与该怪经验分配。
- 权重为物理 3、魔法 3、召唤 3、控制 1。
- 1000 点经验按权重整数分配，余数用最大余数法；平局按 `generalProgressId`。
- 天兵永远不进入账本，但天兵完成最后一击时，该玩家自己的合格神将仍可分配经验。
- 击杀玩家没有合格神将时不分配，经验不转给队友或公共池。

## 10. 幂等与并发

- 玩家动作以 `actionId` 幂等。
- 攻击事件以 `matchId + tick + attackerId + attackSequence` 唯一。
- 死亡结算以 `matchId + enemyId` 唯一。
- 奖励事件引用 `deathSettlementId`，重复执行只返回已有结果。
- 本路清波奖励以 `matchId + playerId + waveNumber` 唯一。
- 一个 Tick 的状态变更在同一个房间串行执行；网络广播失败不能回滚权威状态。

## 11. 验收测试

- 同种子和动作序列重复运行，目标、暴击、伤害和奖励逐事件一致。
- 射程边界内/外的定点距离判断正确。
- 护甲 0、正护甲、高护甲的伤害满足公式且最低伤害为 1。
- 单体、穿透、范围攻击冻结的目标数量符合配置上限。
- 无目标时不进冷却；成功攻击、部署和合成后的计时正确。
- 多个攻击者同 Tick 击杀同一怪物只结算一次死亡。
- 1000 点经验只在击杀玩家的合格神将组合中分配，总和严格为 1000。
- 纯天兵阵容击杀时经验不进入任何神将或公共池；天兵击杀但同玩家有合格神将贡献时可正常分配。
- 队友在循环圈补刀后，斋饭和经验结算权归队友，但原出生路线清空时仍向路线主人发放清波保底。
