# 专项设计：羁绊结算

> 状态：V0.1 专项工作台
>
> 定位：神将与羁绊是核心长线玩法。每个羁绊必须独立完成玩法目标、结构化效果、交互边界、数值模拟和测试验收，不能只按固定 ID 数组判定后直接叠百分比。

## 一、基础规则

1. 羁绊按玩家独立计算，只统计该玩家在棋盘上字符连续、顺序正确且处于激活状态的神将逻辑聚合体。
2. 召唤托盘中的字符、被拆开而失活的神将和其他玩家的神将不计入普通羁绊。神将是否处于「固定」状态不影响羁绊。
3. 同名神将对同一玩家单局唯一，因此成员集合使用 `Set<generalId>` 判定。
4. 字符落位形成神将、字符移走导致失活时重新计算羁绊；固定/解除固定和不破坏组合的整体迁移不触发羁绊变化。正常战斗 Tick 不重复扫描全部组合。
5. 羁绊失效时移除带该 `synergyId` 来源的修改器，不反向修改基础属性。
6. 羁绊只强化基础属性或已有技能效果，不凭空增加独立主动技能。
7. 跨玩家合作羁绊、敌我对抗羁绊如未来加入，使用独立作用域，不改变普通羁绊语义。

## 二、结算流程

```text
神将组合状态发生变化
→ 生成该玩家 activeGeneralIds
→ 对候选羁绊做固定成员包含判断
→ 比较上一帧 activeSynergyIds
→ 对新增羁绊挂载结构化修改器
→ 对失效羁绊按 sourceSynergyId 精确移除
→ modifierVersion + 1
→ 重算受影响神将及其存活召唤物
→ 向前端发送羁绊激活/失效事件与属性差异
```

候选羁绊可以从“新上阵神将 → 关联羁绊索引”获取，无需每次遍历全库。

## 三、羁绊配置结构

```json
{
  "synergyId": "thunder_duo",
  "name": "雷部双神",
  "category": "archetype_small",
  "members": ["leigong", "dianmu"],
  "activationScope": "owner_deployed_generals",
  "target": {
    "scope": "synergy_members"
  },
  "effects": [
    {
      "type": "stat_modifier",
      "stat": "magicDamageBonus",
      "operation": "add_ratio",
      "value": 0.2,
      "stackGroup": "synergy_magic_damage"
    },
    {
      "type": "effect_parameter_patch",
      "targetEffectId": "dianmu_lightning_chain_bounce",
      "parameter": "bounceCount",
      "operation": "add_flat",
      "value": 1
    }
  ],
  "conflicts": [],
  "balanceBudget": 2,
  "status": "prototype"
}
```

神将配置中的 `synergyIds` 仅作为构建时生成的 UI 反向索引，羁绊配置才是成员与效果的唯一权威来源，避免两边手工维护后不一致。

## 四、属性叠加原则

羁绊修改器进入统一效果系统的“羁绊常驻修改”层：

- 同一属性的普通百分比默认加法汇总；
- 标记为独立乘区的效果必须经过专项审批，并占用更高数值预算；
- “全属性”禁止直接作为运行时属性，必须展开为明确白名单；
- 冷却缩减、暴击率、攻速、控制和易损最终受全局上限约束；
- 修改技能范围、弹射次数、召唤上限等参数时使用 `effect_parameter_patch`；
- 召唤物是否受益必须由目标选择器明确声明，不从“友军”“全属性”猜测。

## 五、每个羁绊的专项卡模板

每个羁绊定稿前必须补齐：

1. 玩法目标：鼓励何种阵容和站位。
2. 成型成本：成员品质、平均所需字符数、占用地块数。
3. 触发对象：成员、全队、小兵、召唤物或指定流派。
4. 结构化效果：类型、属性、操作、数值、叠加组。
5. 与成员技能的具体交互。
6. 与其他羁绊、武器、主动/被动道具的组合风险。
7. 组合/拆开、升级、固定迁移和召唤物存续时的边界行为。
8. 理论收益预算与满配极限值。
9. 必测用例和性能预算。
10. 数据状态：概念、原型、数值测试、已定稿、已上线。

## 七、首个原型：月宫旧侣

当前实际开发顺序已经改为先完成后羿，因此首个纵向切片选择后羿、嫦娥组成的“月宫旧侣”：

- 两名都是二字紫将，成型成本低；
- 神话关系明确，玩家无需额外学习；
- 后羿为物理远程，嫦娥规划为召唤远程，第二名神将即可验证跨职业羁绊；
- 第一版只验证成员属性修改，避免尚未开发嫦娥时提前实现减速参数补丁。

首轮只测试：成员攻击范围 +0.5 格、攻击速度 +10%。不新增独立技能，也不修改减速。权威数据和验收细节见《专项设计-羁绊体系V1与月宫旧侣.md》。

## 八、专项验收门槛

一个羁绊只有同时满足以下条件才能标为“已定稿”：

1. 成员、触发范围和失效条件无歧义。
2. 所有效果均可由统一效果系统表达。
3. 与所有成员技能、专武和已定稿重叠羁绊完成组合测试。
4. 满配时不突破攻速、冷却、控制、易损和召唤物数量上限。
5. 有可复现的无羁绊/有羁绊战斗模拟数据。
6. 组合、拆开、固定迁移、断线重连和回放结果一致。
7. UI 能说明羁绊当前为何激活、影响谁、带来多少最终收益。
