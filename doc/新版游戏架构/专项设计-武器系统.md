# 专项设计：武器系统

> 状态：V0.1 架构草案
>
> 当前范围：PVE、武器碎片、品质合成、局外佩戴、双武器槽、流派武器、红色专属武器。

## 一、核心规则

1. 武器以武器碎片形式掉落并保存到玩家局外账户。
2. 武器分为绿、蓝、紫、橙、红 5 个品质。
3. 每种武器使用自己的 `weaponId` 碎片，不使用可以任意合成所有武器的万能碎片作为基础规则。
4. 达到对应碎片数量后，可在局外合成并永久解锁该武器。
5. 武器只能在局外为神将佩戴、卸下或切换；进入对局后锁定，局内无法进行任何武器操作。
6. 每个神将最多配置 2 件武器。
7. 绿、蓝、紫、橙武器按物理、魔法、召唤、控制四类神将分别设计。用户需求中的“辅助类”按当前新版口径归入控制类，不再保留独立辅助流派。
8. 红色武器必须为每个神将至少设计 1 件专属武器，同时允许存在少量红色通用武器。
9. 每件红色专属武器必须与对应神将一起作为专项开发、平衡和验收，不能脱离神将单独上线。

## 二、品质与合成

| 品质 | 合成所需同武器碎片 | 定位 |
| --- | ---: | --- |
| 绿色 | 1 | 基础属性或单一轻量效果，快速形成首件武器 |
| 蓝色 | 2 | 明确服务一种流派基础打法 |
| 紫色 | 3 | 提供可感知的技能或攻击方式强化 |
| 橙色 | 4 | 构筑核心，允许改变部分技能参数或流派节奏 |
| 红色 | 5 | 最高品质；包含神将专武与少量通用终局武器 |

首版采用“达到数量直接解锁”的合成方式，不设置合成失败、随机词条、强化等级或同武器升星。多余碎片的兑换、分解和后续升阶用途留到经济系统专项。

## 三、碎片生命周期

### 1. 局内掉落

Boss、精英怪或关卡奖励可以产生：

```ts
interface WeaponFragmentDrop {
  dropId: string
  weaponId: string
  quality: 'green' | 'blue' | 'purple' | 'orange' | 'red'
  count: number
  sourceKind: 'boss' | 'elite' | 'stage_reward'
  sourceId: string
  ownerPlayerId: string
}
```

碎片掉落必须在产生时绑定玩家归属，避免多人 PVE 中抢拾和重复结算。客户端展示掉落动画，服务端记录待结算清单。

### 2. 对局结算

对局结束时，服务端把合法待结算碎片写入局外账户：

```ts
interface WeaponFragmentBalance {
  playerId: string
  weaponId: string
  count: number
  updatedAt: string
}
```

首版已经确定：胜利、失败、主动退出和断线永久退出都完整保留玩家本局已经通过权威掉落事件获得的碎片，不按完成波次折损。客户端不能直接增加永久碎片；具体幂等事务和分档金币/购买权见《专项设计-局外结算与购买权.md》。

### 3. 合成

合成操作仅在局外发生：

1. 校验武器定义存在；
2. 校验玩家未解锁该武器；
3. 校验对应 `weaponId` 碎片达到品质门槛；
4. 原子扣除碎片并写入永久武器库存；
5. 返回新的库存与碎片余额。

重复合成、重复请求和断线重试必须通过 `requestId` 保证幂等。

## 四、流派武器结构

### 1. 物理武器

主要服务：攻击力、攻击速度、暴击、暴击伤害、破甲、穿透、击退和单体/Boss 增伤。

风险边界：不能同时无上限提高攻速、穿透目标数和击退距离；百分比生命伤害必须设置 Boss 系数与单次上限。

### 2. 魔法武器

主要服务：法强、技能伤害、范围、弹射、持续伤害、元素区域和法术易损。

风险边界：全屏、多段、持续区域和弹射必须受每秒效果事件预算限制。

### 3. 召唤武器

主要服务：召唤物攻击/攻速、数量上限、持续时间、生成位置、继承比例和召唤物功能变化。

风险边界：每件武器必须声明对召唤数量、实体数量和网络同步量的影响；不得绕过每位神将的召唤上限。

### 4. 控制武器

主要服务：减速、眩晕、定身、封禁、击退、聚怪、易损和控制抗性削减。

风险边界：不能突破统一效果系统的硬控递减、Boss 单次控制上限、最低移速和最大路径位移。

## 五、通用武器与适配规则

武器定义必须声明适配范围：

```ts
interface WeaponCompatibility {
  allowedArchetypes?: Array<'physical' | 'magic' | 'summon' | 'control'>
  allowedGeneralIds?: string[]
  excludedGeneralIds?: string[]
  exclusiveGeneralId?: string
}
```

- 绿、蓝、紫、橙武器默认使用 `allowedArchetypes`；
- 红色通用武器可以使用一个或多个 `allowedArchetypes`；
- 红色专属武器必须使用 `exclusiveGeneralId`，其他神将不可佩戴；
- 同一武器是否允许在两个槽位重复佩戴，首版统一设为不允许。

## 六、局外佩戴与对局快照

### 1. 局外配置

```ts
interface GeneralWeaponLoadout {
  playerId: string
  generalId: string
  weaponSlots: [string | null, string | null]
  version: number
}
```

保存时校验：

- 玩家已经永久解锁该武器；
- 武器适配该神将；
- 两个槽位没有重复武器；
- 每个槽位最多一件，合计不超过两件；
- 专武只能装给对应神将。

### 2. 开局快照

创建 PVE 对局时，服务端把所有可用神将的局外武器配置复制为不可变的 `matchWeaponLoadoutSnapshot`。

- 局中即使玩家在其他页面更换武器，也不影响已经开始的对局；
- 神将尚未组合时，武器效果不生效；
- 神将组合激活后，自动挂载快照中的武器效果；
- 神将被拆开后，武器效果随神将失活而移除；重新组合时恢复同一快照；
- 局内不提供装备、卸下、切换或交换武器动作。

## 七、武器配置模型

```json
{
  "schemaVersion": 1,
  "weaponId": "thunderwood_staff",
  "name": "雷木杖",
  "quality": "purple",
  "fragmentRequirement": 3,
  "compatibility": {
    "allowedArchetypes": ["magic"]
  },
  "effects": [
    {
      "type": "stat_modifier",
      "target": { "scope": "equipped_general" },
      "stat": "magicDamageBonus",
      "operation": "add_ratio",
      "value": 0.12,
      "durationMs": null,
      "stackGroup": "weapon_magic_damage"
    }
  ],
  "tags": ["magic", "general_weapon"]
}
```

武器所有能力必须通过《专项设计：统一效果系统》表达。展示文本可以单独配置，但不能从自然语言反向解析逻辑。

## 八、红色专属武器专项

每个神将至少拥有 1 件红色专武。专武目标是强化或改变该神将最有辨识度的机制，不是简单提供最高数值。

当前专项队列按《神将体系架构》实际配置表统计如下：

| 流派 | 已列神将 | 数量 |
| --- | --- | ---: |
| 物理 | 杨戬、哪吒、后羿、沙悟净、猪八戒、玉皇大帝 | 6 |
| 魔法 | 雷公、电母、镇元子、如来佛祖、菩提老祖 | 5 |
| 召唤 | 李靖、嫦娥、孙悟空、太乙真人 | 4 |
| 控制 | 寿星、唐三藏、白龙马、毗蓝婆、观音菩萨、太上老君 | 6 |
| 合计 | 当前已定义神将 | 21 |

当前 21 名神将全部进入专武专项队列；红色通用武器不能替代任一神将的专武义务。

每个“神将 + 专武”专项必须回答：

1. 神将基础玩法在无专武时是否完整可用；
2. 专武改变哪一个已有技能参数或战斗决策；
3. 是否与第二武器槽形成过强乘区；
4. 是否突破攻速、控制、召唤数量、范围或效果事件预算；
5. 与全部相关羁绊的组合上限；
6. 多格汉字神将拆开、重新组合时的武器效果生命周期；
7. 无专武、专武单持、专武加最强通用武器三组模拟数据；
8. 是否有清晰的专属表现，但仍保持纯汉字视觉方向。

专武与神将共享开发状态：`概念 → 结构化配置 → 单体测试 → 羁绊/双武器组合测试 → 性能测试 → 定稿 → 上线`。神将未通过专项验收时，其专武不能提前上线；专武未通过验收时，不阻塞神将基础版本上线。

## 九、红色通用武器

红色通用武器数量应明显少于红色专武，负责支持跨神将构筑，例如：

- 物理通用：把部分单体伤害转为穿透，但降低单体倍率；
- 魔法通用：扩大区域持续时间，但限制同屏区域数量；
- 召唤通用：减少召唤数量、提高单体召唤物质量；
- 控制通用：降低硬控时长、提高易损或控制覆盖率。

通用红武不能在所有神将上都成为无脑最优解，必须具有可感知的收益与代价。

## 十、首版验收用例

1. 绿/蓝/紫/橙/红武器分别严格需要 1/2/3/4/5 个同武器碎片。
2. 碎片不足、武器已解锁或重复请求时不会重复扣除。
3. 未解锁、流派不符或专属角色不符的武器不能保存到槽位。
4. 每个神将最多两件武器，同一武器不能重复装备。
5. 开局后局外换装不影响当前对局。
6. 神将未组合时武器不生效，组合后生效，拆开后精确移除，重新组合后恢复。
7. 武器效果可以展开到具体来源，回放结果保持一致。
8. 红色专武必须通过对应神将、羁绊和第二武器组合测试。
