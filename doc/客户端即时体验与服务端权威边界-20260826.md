# 客户端即时体验与服务端权威边界（2026-08-26）

## 结论

当前架构原本只完成了“服务器负责可信结果”：服务端权威引擎决定随机数、敌人移动、伤害、资源、动作合法性、持久化与结算；客户端不预扣资源，也不自行生成战斗结果。

客户端已有本地 Phaser 渲染、战斗表现和怪物逐帧插值，但玩家操作仍是发送 `SEND_ACTION` 后等待下一份 `TICK_UPDATE`，因此“客户端负责即时体验”的边界不完整。

## 本次调整后的职责

### 客户端

- 输入发生后立即创建仅限表现的 action intent。
- 空间类指令立即在目标格显示本地反馈；非空间类指令显示本地发送状态。
- 维护最多 8 条、最长 3 秒的有界意图账本。
- 收到 `ACTION_ACCEPTED` 后只把反馈标为服务器已接收，不修改棋盘、资源、伤害或冷却。
- 下一份晚于接收 tick 的权威状态到达后自动清除意图；拒绝、断线、完整重同步或超时也会安全清除。
- 怪物位置继续由权威坐标驱动，但在本地按渲染帧线性插值，不让 200ms 网络广播直接表现成跳步。

### 服务端

- 继续拥有游戏状态、随机数、规则执行、动作顺序、持久化和结算的唯一权威。
- 动作接收返回稳定的 `requestId`、`actionId` 和 `serverTick`。
- 动作拒绝也回传对应 `requestId`，客户端只撤销匹配的本地表现。
- 客户端提交的数据不能直接改变账号奖励或最终结果。

## 为什么没有把战斗计算迁到浏览器

这是联机 PVE，并包含账号、奖励和结算。浏览器不是可信执行环境；如果把伤害、资源或随机数交给客户端，再依靠本地反作弊上报，篡改客户端可以同时篡改游戏结果和检测结果。

流畅体验并不要求客户端拥有结果权威。正确边界是：客户端可以预测和立即表现，服务器负责接受、拒绝、纠正与结算。本次调整采用的正是这一边界。

## 验收

- 前后端 TypeScript 构建通过。
- 客户端意图回归覆盖空间目标、服务器确认、权威帧对账、拒绝、超时和容量上限。
- Chromium 真实链路确认本地反馈先于权威帧出现，随后自动清除。
- 高事件实战末段 52.5 FPS、P95 25.3ms、长任务 0。
- 80 敌人压力场景末段 62.4 FPS、P95 18.2ms、长任务 0。
- 控制台错误 0，全部性能门槛通过。
