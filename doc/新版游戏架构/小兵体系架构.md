# 小兵体系架构

> 状态：V0.1，第一版实现依据  
> 领域名称：代码统一使用 `soldier`，产品文案使用“天兵/天将”
> 首版 1～5 级数值见《专项设计-天兵与小怪数值平衡.md》

## 1. 定位

天兵是神将尚未组成时的核心战力，必须能够独立完成前期守线，而不是廉价占位单位。表现保持纯汉字；第一版不制作人物模型。

| soldierType | 字符 | 名称 | attackShape | 作用 |
|---|---|---|---|---|
| `blade` | 刀 | 天刀兵 | `single` | 短程单体 |
| `spear` | 枪 | 天枪兵 | `line_pierce` | 直线穿透 |
| `bow` | 弓 | 天弓兵 | `single` | 远程单体 |
| `cavalry` | 骑 | 天骑兵 | `radius` | 范围群攻 |

## 2. 统一规则

- 等级范围 1～5。
- 天兵没有生命值、受击、死亡和经验系统。
- 棋盘上的天兵占 1 个格子、1 人口；托盘中的天兵不占人口。
- 天兵自动选敌和攻击，玩家不能手动指定目标或释放技能。
- 天兵不穿戴神将武器。
- 第一版不出售、不回收、不分解、不自动合成。

## 3. 静态配置

```ts
type SoldierType = 'blade' | 'spear' | 'bow' | 'cavalry';
type DamageType = 'physical' | 'magic';
type AttackShape = 'single' | 'line_pierce' | 'radius';

interface SoldierDefinition {
  soldierType: SoldierType;
  glyph: '刀' | '枪' | '弓' | '骑';
  displayName: string;
  damageType: DamageType;
  attackShape: AttackShape;
  baseAttackByLevel: [number, number, number, number, number];
  attackIntervalMsByLevel: [number, number, number, number, number];
  attackRangeByLevel: [number, number, number, number, number];
  critChanceBpsByLevel: [number, number, number, number, number];
  critDamageBpsByLevel: [number, number, number, number, number];
  pierceCountByLevel?: [number, number, number, number, number];
  radiusByLevel?: [number, number, number, number, number];
  maxTargetsByLevel?: [number, number, number, number, number];
}
```

约束：

- 所有等级数组长度必须为 5，值必须为整数。
- `attackIntervalMs` 必须大于 0，暴击率范围为 0～10000 基点。
- 暴击伤害基点不低于 10000；例如 15000 表示 150%。
- 穿透数量和群攻上限必须显式配置，不能用 `0` 暗示无限。
- 数值先由配置驱动，不在架构文档写死；每次升级后的综合 DPS 应明显高于升级前单兵。

## 4. 运行时状态

```ts
interface SoldierState {
  entityId: string;
  ownerPlayerId: string;
  soldierType: SoldierType;
  level: 1 | 2 | 3 | 4 | 5;
  location: TrayLocation | BoardLocation;
  nextAttackTick: number;
  createdSequence: number;
}
```

所有战斗数值由 `SoldierDefinition + level + MatchConfigSnapshot` 推导，不重复写入状态。这样配置快照不变时，断线重连和回放可以得到一致结果。

## 5. 合成规则

### 5.1 合法条件

只有同时满足以下条件才可合成：

- 两个实体均为天兵。
- 所有者相同。
- `soldierType` 相同。
- `level` 相同。
- 等级小于 5。
- 两个实体不是同一个实体。
- 请求中的棋盘/托盘修订号仍然有效。

### 5.2 原子结果

服务端在一个事务中：

1. 冻结源和目标位置。
2. 再次验证合法条件与人口。
3. 删除两个旧实体。
4. 在目标位置创建一个 `level + 1` 的新实体。
5. 源位置变为空位。
6. 新实体的首次攻击时间设置为 `currentTick + fullAttackIntervalTicks`。
7. 若两个旧实体都在棋盘，已用人口由 2 减为 1；其他位置组合按最终棋盘实体数量重算人口。
8. 增加修订号并广播 `SOLDIER_MERGED`。

新建实体而不是修改其中一个旧实体，可避免旧攻击计时器、旧客户端选择态或重复请求附着到升级后天兵。

### 5.3 允许的位置组合

- 棋盘 + 棋盘。
- 托盘 + 棋盘。
- 棋盘 + 托盘。
- 托盘 + 托盘。

目标位置保留升级后的天兵。若目标在棋盘，必须通过人口校验；合成释放的人口必须与整个事务一起计算，不能先拒绝后释放。

## 6. 动作协议

```ts
interface MergeSoldiersAction {
  type: 'MERGE_SOLDIERS';
  actionId: string;
  sourceEntityId: string;
  targetEntityId: string;
  expectedBoardRevision: number;
  expectedTrayRevision: number;

```

推荐拒绝码：

- `ENTITY_NOT_FOUND`
- `NOT_OWNER`
- `NOT_SOLDIER`
- `TYPE_MISMATCH`
- `LEVEL_MISMATCH`
- `MAX_LEVEL`
- `STALE_REVISION`
- `INVALID_LOCATION`
- `POPULATION_LIMIT`
- `DUPLICATE_ACTION`

## 7. 选敌和攻击

- 攻击结算完全在服务端。
- 单体攻击选射程内路线进度最靠前的小怪。
- 枪兵先确定主目标，再按攻击方向取得直线上的额外目标。
- 骑兵先确定主目标，再取得目标周围半径内的小怪。
- 一次攻击开始时冻结本次目标集合；同 Tick 后续移动不改写这次攻击。
- 具体稳定排序、暴击和伤害公式见《专项设计-基础战斗事件与直接攻击.md》。

## 8. 验收测试

- 四类天兵均能被配置校验器加载，五级数组缺项时启动失败。
- 两个同类同级天兵可合成；不同类、不同级、5 级不能合成。
- 重复提交同一个 `actionId` 不会重复生成单位。
- 两个上场单位合成后人口从 2 降到 1。
- 托盘与棋盘跨区域合成后，空位、人口和目标位置正确。
- 合成后不会继承旧单位即将完成的攻击。
- 同种子、同动作、同 Tick 下，枪兵穿透和骑兵群攻目标集合一致。
