# 小怪与波次基础架构

> 状态：V0.1，第一版普通小怪实现依据  
> 范围：普通小怪与基础波次；Boss 另立专项
> 第 1～20 波首版数值见《专项设计-天兵与小怪数值平衡.md》
> 关卡编排与 Boss 插件见《专项设计-PVE关卡与Boss分期架构.md》

## 1. 表现与边界

普通小怪只用单个汉字显示，不制作角色模型。通用字可用“鬼、怪、妖、魔、魅”；场景可以覆盖专属字，例如盘丝洞使用“蛛、蛇”。

普通小怪：

- 不携带技能。
- 不攻击天兵、神将或字符。
- 不拥有闪避、格挡、护盾、韧性、经验等级等隐藏战斗属性。
- 只沿既有路线循环移动，具体越线/绕圈失败条件沿用成熟战场规则。

## 2. 唯一四项战斗属性

1. 生命值。
2. 护甲。
3. 魔抗。
4. 移动速度。

运行时可以保存 `currentHp`，但它是生命值的当前状态，不算第五类属性。实例 ID、位置、路线进度、奖励归属等是系统状态，不是战斗属性。

## 3. 静态配置

```ts
interface MinionEnemyDefinition {
  enemyTypeId: string;
  glyph: string;
  displayName: string;
  sceneTags: string[];
  baseMaxHp: number;
  baseArmor: number;
  baseMagicResistance: number;
  baseMoveSpeedMilliCellsPerSecond: number;
  riceReward: 1;
  xpRewardPoint: 1000;
}

interface WaveEnemyScaling {
  maxHpMultiplierBps: number;
  armorAdd: number;
  magicResistanceAdd: number;
}
```

- 普通小怪 `riceReward` 固定为 1。
- `1000 xpRewardPoint` 在 UI 中显示为 1.0 经验。
- 波次只可改变生命、护甲、魔抗。
- `baseMoveSpeedMilliCellsPerSecond` 不允许被波次缩放。
- 移速变化只能来自 Boss 技能或后续明确注册的效果，效果消失后恢复基础值。

## 4. 运行时状态

```ts
interface MinionEnemyState {
  entityId: string;
  enemyTypeId: string;
  glyph: string;
  spawnSequence: number;
  waveNumber: number;
  homeLanePlayerId: string;
  homeSlotId: 'P1' | 'P2' | 'P3' | 'P4';
  routeZone: 'private_lane' | 'public_loop';
  pathProgressMilli: number;
  threatProgressMilli: number;
  lapCount: number;
  currentHp: number;
  maxHp: number;
  armor: number;
  magicResistance: number;
  baseMoveSpeedMilliCellsPerSecond: number;
  currentMoveSpeedMilliCellsPerSecond: number;
  lastDamagedByPlayerId: string | null;
  lifecycle: 'alive' | 'dying' | 'removed';
}
```

所有数值均用整数或定点整数。路径进度不得使用会导致跨平台漂移的累计浮点数。

## 5. 场景字池

场景配置决定可刷新的 `enemyTypeId`，字形只负责表现，不能拿字形本身当唯一 ID。

| 场景示例 | 推荐字池 |
|---|---|
| 花果山 | 怪、妖、猴、猿 |
| 火焰山 | 妖、魔、火、焰 |
| 盘丝洞 | 魅、妖、蛛、蛇 |
| 流沙河 | 怪、鬼、鱼、鼋 |
| 白虎岭 | 鬼、魅、骨、尸 |

第一条内部可玩切片只需“鬼、妖、魔、蛛”四个配置，验证字池切换后再扩内容。

## 6. 波次生成

- 服务端根据 `MatchConfigSnapshot` 和波次脚本生成小怪。
- 每个实例获得单调递增的 `spawnSequence`。
- 生命按基点倍率计算，护甲和魔抗按整数加值计算。
- 对同一配置快照和随机种子，出生类型、时间和顺序必须可复现。
- 波次层不直接写奖励逻辑，奖励读取小怪定义。
- 多人直接沿用原项目的玩家路线槽：P1～P4 各自生成本路小怪，小怪进入公共循环圈后可被其他玩家攻击。生成预算按有效玩家数扩展，为每条有效路线生成该波应有的小怪。

## 7. 多人击杀奖励与清波保底

每只小怪保存出生路线主人，但出生路线不决定击杀奖励：

- 最后一次有效伤害的 `sourcePlayerId` 写入 `lastDamagedByPlayerId`。
- 该玩家获得死亡小怪的 1 斋饭和 1000 点神将经验结算权。
- 召唤物、持续伤害和神将技能都必须映射回所属玩家。
- 天兵完成最后一击时，斋饭仍给天兵所属玩家；该玩家最近 5 秒有合格神将贡献才可分配经验，否则经验损失。
- 其他玩家救场或在公共循环圈补刀可以取得击杀奖励，不做补偿回拨。
- 无玩家来源的关卡环境伤害不发击杀斋饭和神将经验。

为避免弱者恒弱，每位玩家每波另有一次本路清波奖励：

```text
laneClearRiceReward(waveNumber) = 5 × waveNumber
```

- 第 1 波 5、第 2 波 10、第 3 波 15，按等差数列增长。
- 只有该玩家路线本波已经完成全部出怪，且本路本波出生的所有小怪均已死亡，才算清波。
- 小怪进入公共循环圈后仍属于原出生路线的清波计数；由队友击杀同样会使该路线存活数减 1。
- 各路线独立判断，谁先清完谁先领取，不等待其他玩家。
- 发放键为 `matchId + playerId + waveNumber`，重复 Tick、重连和回放不会重复发放。

## 8. 移动与死亡顺序

每个 Tick：

1. 按 `entityId` 稳定顺序推进路径进度。
2. 应用仍有效的 Boss 移速增益；无增益时使用基础移速。
3. 处理绕圈/超载条件。
4. 战斗阶段结算伤害。
5. 首次发现 `currentHp <= 0` 时将状态改为 `dying`。
6. 产生唯一 `ENEMY_DIED` 事件。
7. 向最后有效伤害玩家发放 1 斋饭。
8. 在该玩家自己的合格神将之间结算严格 1000 点经验。
9. 标记 `removed` 并从下个公开快照移除。
10. 更新出生路线的本波存活计数；若已完成出怪且归零，立即发放该路线清波奖励。

死亡事务由 `deathSettlementId = matchId + entityId` 幂等保护。

## 9. 验收测试

- 普通小怪配置出现第五类战斗属性时校验失败。
- 波次提升只改变生命、护甲、魔抗，基础移速逐波完全一致。
- 固定 Tick 数后的路径进度可重复。
- 同一小怪受到同 Tick 多次致死伤害时只产生一次死亡、1 斋饭和 1000 点经验。
- 4 人房间中，击杀斋饭归最后有效伤害玩家；公共循环圈补刀可以取得奖励。
- 4 条路线在不同 Tick 清完同一波时，各自立即获得对应奖励且不重复。
- 断线重连后小怪生命、路线进度、出生路线、最后伤害玩家和生命周期一致。
- “蛛、蛇”等场景字由配置产生，逻辑层不依赖字形判断类型。
