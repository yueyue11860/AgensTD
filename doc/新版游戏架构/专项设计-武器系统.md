# 专项设计：武器系统

> 三难度品质上限、5/10/15/20 波里程碑掉落表和困难通关专武保底，以《专项设计-PVE三难度解锁、数值与武器掉落.md》为准。本文仍是武器目录、合成、双槽配装和战斗效果的权威文档。

> 状态：V1.0 可开发设计稿
>
> 适用范围：PVE、局外永久武器、武器碎片、Boss 个人掉落、品质合成、双武器槽、通用武器、21 件红色专属武器
>
> 关联文档：《神将体系架构》《专项设计-统一效果系统.md》《专项设计-羁绊结算.md》《专项设计-局外结算与购买权.md》

## 一、设计目标与锁定结论

武器是局外长期收集和单神将构筑轴，负责改变某名神将的属性、攻击方式或已有技能参数；羁绊负责阵容关系，道具负责整局规则和玩家主动操作，三者不能互相替代。

首版锁定以下规则：

1. 武器只以对应 `weaponId` 的碎片形式掉落，绿、蓝、紫、橙、红分别需要 1、2、3、4、5 个同武器碎片合成。
2. 合成后永久解锁该武器。首版采用“图鉴解锁”而非“武器实例库存”：一件已解锁的通用武器可以被配置给多个适配神将，但同一神将的两个槽位不能重复装备同一 `weaponId`。
3. 每个神将固定 2 个武器槽；武器只能在局外佩戴、卸下和切换。
4. 创建对局时服务端生成不可变武器快照。局中不能换装，局外随后发生的换装也不影响已开始对局。
5. 绿、蓝、紫、橙各先提供物理、魔法、召唤、控制四类通用武器各 1 件，共 16 件。
6. 红色先提供四流派通用武器各 1 件，并为当前 21 名神将各提供 1 件专属武器，共 25 件红武。
7. 红色专武必须使用 `exclusiveGeneralId`，只能由对应神将装备；通用武器按 `allowedArchetypes` 判断适配。
8. 武器不拥有随机词条、强化等级、洗练、升星、耐久和合成失败。先把固定效果与双槽组合做稳定。
9. 武器效果只强化已有战斗系统或使用已注册的新触发器，禁止从 UI 描述文本反向解析逻辑。
10. 下文数值是首轮联调基准，不是最终平衡结论；ID、适配、生命周期、目标和叠加语义属于结构性结论。

首版明确不做：局内换装、武器交易、玩家间赠送、万能碎片、随机词条、同武器多星级、武器主动按钮、扩地效果以及 PVP 数值。

## 二、核心对象与生命周期

### 2.1 武器定义

```ts
type WeaponQuality = 'green' | 'blue' | 'purple' | 'orange' | 'red'
type GeneralArchetype = 'physical' | 'magic' | 'summon' | 'control'

interface WeaponDefinition {
  schemaVersion: 1
  weaponId: string
  name: string
  quality: WeaponQuality
  fragmentRequirement: 1 | 2 | 3 | 4 | 5
  compatibility: {
    allowedArchetypes?: GeneralArchetype[]
    allowedGeneralIds?: string[]
    excludedGeneralIds?: string[]
    exclusiveGeneralId?: string
  }
  uniqueGroup?: string
  statModifiers: StructuredEffect[]
  triggers: WeaponTriggerDefinition[]
  parameterPatches: EffectParameterPatch[]
  eventBudget: WeaponEventBudget
  ui: {
    shortDescription: string
    detailDescription: string
    iconKey: string
  }
  status: 'prototype' | 'testing' | 'released'
}
```

`fragmentRequirement` 必须与品质严格一致，配置加载阶段直接校验。红色专武必须有且只能有一个 `exclusiveGeneralId`。

### 2.2 玩家永久账户

```ts
interface PlayerWeaponAccount {
  playerId: string
  fragmentBalances: Record<string, number>
  unlockedWeaponIds: string[]
  loadoutsByGeneralId: Record<string, {
    slots: [string | null, string | null]
    version: number
    updatedAt: string
  }>
  version: number
}
```

同一 `weaponId` 只解锁一次。重复合成请求返回已经解锁的当前结果，不重复扣碎片。

### 2.3 生命周期

```text
Boss/关卡触发个人掉落
→ 写入本局 pendingFragmentDrops
→ 玩家退出、失败或通关
→ 幂等写入局外 fragmentBalances
→ 局外合成永久解锁
→ 为神将保存双槽配置
→ 创建房间时复制为 matchWeaponLoadoutSnapshot
→ 神将组合激活时挂载武器来源
→ 神将拆开时移除武器来源
→ 同一神将重新组合时恢复原快照，不重复触发首次挂载事件
```

## 三、品质、合成与多余碎片

| 品质 | 所需同武器碎片 | 设计权限 | 首版定位 |
| --- | ---: | --- | --- |
| 绿色 | 1 | 单一基础属性 | 快速得到第一件可用武器 |
| 蓝色 | 2 | 两项基础属性或一个轻机制 | 明确流派方向 |
| 紫色 | 3 | 条件触发、状态或攻击方式强化 | 形成局部玩法变化 |
| 橙色 | 4 | 改变攻击/技能节奏，必须带预算或代价 | 构筑核心 |
| 红色 | 5 | 强机制通用武器或神将专武 | 终局构筑 |

### 3.1 合成事务

客户端发送 `CRAFT_WEAPON(requestId, weaponId, expectedAccountVersion)`，服务端按顺序：

1. 校验请求幂等键；
2. 校验武器定义存在且当前可获得；
3. 校验尚未解锁；
4. 按定义品质重新计算门槛，忽略客户端提交数量；
5. 在同一事务内扣除碎片、加入 `unlockedWeaponIds`、增加账户版本；
6. 写入 `WEAPON_UNLOCKED` 账户事件并返回新余额。

校验失败不扣碎片。并发两次合成只能有一次成功。

### 3.2 解锁后的同名碎片

首版不删除已经持有的多余碎片，也不自动折算金币，避免在经济尚未平衡时制造不可逆兑换。掉落与商店生成候选时优先排除已解锁武器；只有对应品质已全部解锁时，才允许出现已解锁武器碎片。多余碎片以后可用于武器外观或精通系统，但当前不产生战斗效果。

## 四、Boss 个人掉落与局外商店

### 4.1 多人 PVE 归属

斋饭和神将经验仍按最后击杀玩家结算。武器碎片属于长期账户资源，为避免 Carry 玩家独占，采用独立个人掉落：

- 第 5、10、15、20 波 Boss 正式死亡时，每名仍在房间且未永久退出的玩家各自进行一次权威掉落；
- 各玩家结果互不影响，不在地面争抢，不因谁完成最后一击而转移；
- 客户端只播放属于自己的碎片结果；
- 已永久退出的玩家保留退出前获得的碎片，但不参加后续 Boss 掉落；
- 所有随机数来自 `matchSeed + playerId + bossKillSequence`，进入回放。

### 4.2 首轮掉落表

| Boss 波次 | 每人基础碎片数 | 品质权重 | 设计目的 |
| --- | ---: | --- | --- |
| 第 5 波 | 1 | 绿 75%、蓝 25% | 尽早形成首件武器 |
| 第 10 波 | 1 | 绿 30%、蓝 45%、紫 25% | 推进基础流派构筑 |
| 第 15 波 | 1 | 蓝 15%、紫 45%、橙 30%、红 10% | 进入核心构筑 |
| 第 20 波 | 2 | 紫 30%、橙 40%、红 30% | 通关长期奖励 |

先抽品质，再从该品质的可用 `weaponId` 中等权抽取。候选优先级：

1. 未解锁且适配玩家本局曾激活神将的武器；
2. 未解锁的其他武器；
3. 已解锁武器。

专武只有玩家本局拥有或局外图鉴已发现对应神将时才进入普通掉落池，避免新玩家先获得完全无法理解的专武碎片。掉率提升类道具只能修改上述权重或增加额外独立抽取，不能直接写永久库存。

### 4.3 武器碎片购买权

《专项设计-局外结算与购买权.md》中的分类在本专项锁定为：

- `low_tier_weapon_fragment`：只生成绿色或蓝色候选；
- `high_tier_weapon_fragment`：只生成紫色、橙色或红色候选。

每张购买权生成 3 个服务端确定的候选，至少 1 个优先适配上一局激活过的神将；玩家支付金币选择其中 1 个，成功后购买权消耗。未购买、金币不足或请求失败不消耗购买权。

| 碎片品质 | 单个碎片原型价格 |
| --- | ---: |
| 绿色 | 5 局外金币 |
| 蓝色 | 10 局外金币 |
| 紫色 | 15 局外金币 |
| 橙色 | 25 局外金币 |
| 红色 | 40 局外金币 |

购买权不设过期时间。候选以 `entitlementId` 为种子固定，反复打开商店不能刷结果；后续若增加付费刷新，必须另立专项。

## 五、局外佩戴与开局快照

### 5.1 保存规则

```ts
interface GeneralWeaponLoadout {
  playerId: string
  generalId: string
  slots: [string | null, string | null]
  version: number
}
```

保存 `SAVE_WEAPON_LOADOUT` 时服务端校验：

1. 神将与两个武器定义均存在；
2. 玩家已经永久解锁对应武器；
3. 武器适配该神将；
4. 专武的 `exclusiveGeneralId` 与神将一致；
5. 两个槽位不能是同一 `weaponId`；
6. 同一 `uniqueGroup` 的武器不能同时佩戴；
7. 客户端携带的 `expectedVersion` 与当前版本一致。

允许同一件已解锁通用武器出现在多个神将的局外方案中，因为首版是图鉴解锁制，不是唯一武器实例制。

### 5.2 对局快照

```ts
interface MatchWeaponLoadoutSnapshot {
  snapshotVersion: 1
  playerId: string
  accountVersion: number
  byGeneralId: Record<string, {
    slots: readonly [string | null, string | null]
    resolvedDefinitions: readonly WeaponDefinition[]
  }>
}
```

- 快照在玩家加入房间并锁定构筑时生成；
- 房间开始后不可修改；
- 断线重连读取同一快照；
- 神将未组合时武器不生效；
- 神将组合后，按槽位 1、槽位 2 的稳定顺序挂载；
- 拆将时按来源精确移除，持续效果是否自然结束由 `sourceInactivePolicy` 决定；
- 重组恢复原来源，不刷新一次性触发器、内部 CD 或已消耗计数。

## 六、属性、触发器与结算顺序

### 6.1 来源与叠加

每个武器修改器使用以下来源键：

```text
weapon:{matchId}:{playerId}:{generalId}:{slotIndex}:{weaponId}:{effectId}
```

属性结算沿用统一效果系统：

```text
基础值 → 等级 → 武器基础属性 → 羁绊 → 神将被动
→ 被动道具 → 关卡 → 主动道具/临时状态 → 最终上限
```

两件武器修改同一属性时：

- `add_flat` 同层相加；
- `add_ratio` 同层相加；
- `multiply` 只有定义明确标注独立乘区时才能使用；
- 参数补丁按稳定来源顺序结算；
- 全局攻速、冷却、控制、易损、位移和召唤上限始终最后钳制。

### 6.2 首批武器触发器

| 触发器 | 用途 | 必须携带的防爆字段 |
| --- | --- | --- |
| `on_basic_attack_hit` | 普攻命中追加效果 | chance、perTargetIcdMs、maxTriggersPerSecond |
| `on_nth_basic_attack` | 第 N 次普攻 | n、counterScope |
| `on_active_skill_cast` | 主动技能释放 | maxTriggersPerCast |
| `on_active_skill_hit` | 主动技能命中 | perTargetIcdMs、maxTargetsPerCast |
| `on_displacement_success` | 成功位移后 | maxTriggersPerCast |
| `on_status_applied` | 成功施加指定状态 | statusTags、perTargetIcdMs |
| `on_summon_basic_attack` | 召唤物普攻 | summonUnitFilter、maxTriggersPerSecond |
| `on_summoned_enemy_killed` | 召唤物参与击杀 | maxTriggersPerPeriod |
| `on_enemy_killed` | 归属神将参与击杀 | maxTriggersPerSkillCycle |

未注册触发器不能写进配置。武器触发产生的伤害与控制归属装备神将，正常进入该神将贡献账本。

### 6.3 双武器事件预算

每件武器定义 `eventBudget`：

```ts
interface WeaponEventBudget {
  maxExtraDamageEventsPerSecond: number
  maxExtraTargetsPerCast: number
  maxOwnedZones: number
  maxExtraSummons: number
}
```

两个槽位预算相加后还要受全局上限控制。建议首版单神将上限：

- 额外伤害事件不超过 12 次/秒；
- 单次技能额外目标不超过 8；
- 武器来源持续区域不超过 3；
- 武器额外召唤单位不超过 2；
- 武器不能让最终攻速超过 5 次/秒、常驻冷却缩减超过 40%。

`WEAPON_EFFECT_ATTACHED`、`WEAPON_EFFECT_DETACHED`、`WEAPON_TRIGGERED`、`WEAPON_FRAGMENT_DROPPED` 和 `WEAPON_FRAGMENT_SETTLED` 必须包含 `playerId`、`weaponId`、来源槽位、Tick/事务 ID。客户端不能发送这些结果事件。

## 十一、前端页面与交互

### 11.1 武器图鉴

- 按品质和流派筛选；
- 明确显示 `当前碎片/合成所需碎片`；
- 已解锁、可合成、未解锁状态分开；
- 专武卡片显示对应神将与“专属”标识；
- 详情同时展示收益、代价、触发上限和适配范围。

### 11.2 神将装备页

- 选择神将后显示两个武器槽；
- 不适配武器置灰并显示原因；
- 保存前本地预检，服务端仍做最终校验；
- 展示两件武器叠加后的属性预览和潜在上限提示；
- 对局内状态卡只展示开局快照，不出现换装按钮。

### 11.3 掉落与结算

Boss 死亡只展示玩家自己的碎片；结算页按本局来源汇总，区分“已写入永久账户”和“等待重试”。网络重试不能重复播放为第二次掉落。

## 十二、开发分期

### P0：账户与双槽闭环

1. 武器目录、品质校验和碎片余额；
2. Boss 个人掉落与局外幂等结算；
3. 合成永久解锁；
4. 局外双槽配置和对局快照；
5. 绿色四武器接入统一属性系统；
6. 图鉴、合成、装备和状态卡展示。

### P1：四流派纵向切片

1. 每个品质各选一件通用武器；
2. 打通属性、触发器、参数补丁、区域和召唤上限；
3. 完成购买权商店和三候选；
4. 完成后羿“射日神弓”首件专武。

### P2：全量通用武器与 21 专武

按神将既定开发顺序逐件接入；每件独立测试后再做双武器、羁绊和压力组合测试。

### P3：数值与运营

掉落率、金币价格、重复碎片用途、赛季扩展和 PVP 规则另行定稿，不反向破坏 V1 数据结构。

## 十三、验收清单

1. 五种品质只能按 1/2/3/4/5 个同武器碎片合成。
2. 合成、购买和结算重复请求 100 次仍只入账一次。
3. 不适配、未解锁、专属不符、同槽重复和唯一组冲突均被拒绝。
4. 同一通用武器可以配置给多个适配神将，但同一神将不能双持同一武器。
5. 开局后局外换装不影响当前对局，断线重连保持同一快照。
6. 神将组合、拆开、重组时武器来源精确挂载、移除和恢复，不重置内部 CD。
7. 武器效果不能命中仍在出生保护区的小怪。
8. 两件武器、神将被动和羁绊叠加后仍受攻速、冷却、控制、位移、易损和召唤预算限制。
9. 21 名神将都有且只有一件首发红色专武，其他神将不能装备。
10. 同一种子、掉落序列、装备快照和操作输入得到完全一致的战斗与掉落结果。
11. 玩家退出、失败、通关均保留已绑定的个人碎片，退出后不再参加后续 Boss 掉落。
12. UI 可以把最终属性或触发效果展开到具体 `weaponId + slotIndex + effectId`。
